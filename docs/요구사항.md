# 독서 기록 앱 명세 (Android)

2026-10-05 · ann

## 개요

종이책을 읽으며 밑줄 친 문장을 폰으로 찍어 저장하고, 완독 후 별점·한 줄 소감을 남기며, 쌓인 기록으로 AI가 취향 분석·추천·토론을 해주는 **1인용 Android 앱**이다.

현재 사용자는 책 기록을 전혀 하지 않고 기억에만 의존한다. 기록을 안 하는 이유는 입력이 귀찮아서다. 따라서 이 앱의 성패는 기능 수가 아니라 **타이핑을 얼마나 없애느냐**에 달려 있다.

설계 원칙:

- 앱을 열면 2초 안에 카메라가 떠야 한다. 글귀 저장이 가장 자주 쓰는 동작이다.
- 타이핑은 책 제목 검색, 한 줄 소감, OCR 실패 시 페이지 번호에만 허용한다.
- 사용자는 한 명이다. 로그인, 서버, 계정은 만들지 않는다.
- AI 호출은 사용자가 버튼을 눌렀을 때만 일어난다. 백그라운드 호출은 없다.

## 기술 스택

Kotlin + Jetpack Compose로 만들고, 외부 의존은 OCR·도서 검색·AI 세 가지뿐이다.

| 영역 | 선택 | 비고 |
| --- | --- | --- |
| 언어/UI | Kotlin, Jetpack Compose | 단일 모듈, minSdk 26 이상 권장 |
| 로컬 DB | Room (SQLite) | 모든 데이터는 기기 안에만 저장 |
| 카메라 | CameraX | 촬영 후 비트맵을 OCR에 넘기고 사진은 폐기 |
| OCR | Google ML Kit Text Recognition v2 (Korean) | 온디바이스, 무료, 오프라인 동작 |
| 도서 검색 | 알라딘 Open API (ItemSearch, ItemLookUp) | TTB 키 필요(무료, 일 호출 한도 있음). 표지·장르(categoryName)·소개글 제공 |
| AI | Anthropic Messages API | 모델 claude-haiku 계열 기본, 프롬프트 캐싱 사용. 최신 모델명·단가는 구현 시 공식 문서 확인 |
| HTTP | Retrofit 또는 Ktor | 알라딘·Anthropic 호출 |
| 백업 | kotlinx.serialization → JSON 파일 | Storage Access Framework로 내보내기/가져오기 |

API 키는 앱 설정 화면에서 사용자가 직접 입력해 EncryptedSharedPreferences에 저장한다. 코드에 하드코딩하지 않는다. 1인용 앱이므로 중계 서버는 두지 않는다.

## 화면과 사용자 흐름

화면은 6개다. 앱을 열면 카메라가 먼저 뜨고, 나머지는 하단 탭이나 책 상세에서 들어간다.

| 화면 | 역할 | 진입 |
| --- | --- | --- |
| 카메라(홈) | 글귀 촬영. 상단에 현재 선택된 책 이름, 탭하면 책 변경 | 앱 시작 시 |
| 문장 선택 | OCR 결과를 줄 단위로 보여주고 터치로 선택, 페이지 번호 확인 | 촬영 직후 |
| 서재 | 책 목록, 상태별 탭(읽는 중 / 읽고 싶음 / 다 읽음) | 하단 탭 |
| 책 상세 | 표지, 정보, 글귀 목록, 별점·한 줄, 토론 목록, 완독 처리 버튼 | 서재에서 책 탭 |
| 분석·추천 | 분석 실행 버튼, 최신 결과, 추천 책 카드(읽고 싶음에 담기) | 하단 탭 |
| 설정 | API 키 입력, JSON 내보내기/가져오기 | 하단 탭 |

**흐름 1: 글귀 저장 (가장 자주, 목표 10초 이내)**

1. 앱 실행 → 카메라 화면. 상단에 `lastQuoteAt`이 가장 최근인 READING 책이 표시된다. READING 책이 없으면 "책을 먼저 등록하세요" 버튼이 뜬다.
2. 셔터 → ML Kit OCR 실행 (로딩 1초 내외).
3. 문장 선택 화면: 인식된 텍스트를 줄(line) 단위로 나열. 사용자가 원하는 줄을 탭해 선택(복수 가능, 연속 선택 시 하나의 문장으로 합침).
4. 페이지 번호 칸: OCR에서 1~4자리 숫자가 페이지 위치(상단/하단 모서리)에서 잡히면 자동 채움. 못 잡으면 빈 칸, 숫자 키패드로 입력 가능. 건너뛰기 허용.
5. 저장 → 카메라 화면으로 복귀, 토스트 "저장됨 (p.123)". 사진은 메모리에서 폐기.

**흐름 2: 책 등록**

1. 서재 → + 버튼 → 검색창에 제목 입력.
2. 알라딘 ItemSearch 결과를 표지·제목·저자로 나열. 탭하면 등록, 상태는 기본 READING(선택 가능).
3. 결과 없음 또는 오프라인 → "직접 입력" 버튼 → 제목·저자만 받아 등록.

**흐름 3: 완독 처리**

1. 책 상세 → "다 읽었어요" 버튼.
2. 한 화면에서 별점(1~5 별 탭), 한 줄 소감(텍스트 한 줄), 완독일(기본 오늘, 변경 가능) 입력 → 저장. 상태는 DONE.
3. 저장 직후 "이 책에 대해 AI와 이야기해볼까요?" 버튼 노출. 탭하면 토론 시작, 아니면 상세로 복귀.

**흐름 4: 분석·추천**

1. 분석 탭. DONE 책 3권 미만 또는 글귀 10개 미만이면 버튼 비활성 + 남은 수 안내.
2. 버튼 탭 → Claude API 호출 → 취향 해석 글 + 추천 책 목록 표시.
3. 추천 카드의 "읽고 싶음에 담기" 탭 → WANT 상태로 Book 생성.

**흐름 5: 완독 후 토론**

1. AI가 첫 질문을 던진다 (별점·한 줄·글귀를 근거로).
2. 사용자가 텍스트로 답한다. 20턴 도달 시 AI가 마무리 멘트를 하고 입력이 닫힌다.
3. 토론은 Discussion에 저장되고 책 상세에서 다시 볼 수 있다.

## 기능 상세

**글귀 OCR과 문장 선택**

- ML Kit `TextRecognition` Korean 옵션으로 `Text.TextBlock > Line` 구조를 받는다. 화면에는 Line 단위로 나열한다.
- 선택된 줄들은 위에서 아래 순서로 합치되, 줄 끝이 음절 중간(하이픈 없는 한국어 줄바꿈)이면 공백 없이 붙인다. 문장 부호로 끝나면 공백 하나로 잇는다.
- 선택 결과를 저장 전에 편집 가능한 텍스트 칸으로 보여준다. 오타 한두 글자는 여기서 고친다.
- 저장 단위는 "이번 촬영에서 선택한 전체"가 Quote 1건이다. 한 페이지에서 두 군데를 따로 남기려면 두 번 저장한다.

**페이지 번호 자동 인식**

- 이미지 상단 15% 또는 하단 15% 영역에 있는 Line 중 숫자만으로 된 1~4자리 텍스트를 페이지 후보로 본다.
- 후보가 1개면 자동 채움. 2개 이상이면 비워 두고 후보를 칩으로 보여줘 탭 선택.
- 사용자가 직접 입력한 값이 우선한다.

**책 검색**

- 알라딘 `ItemSearch` (Query=제목, QueryType=Title, MaxResults=10, Cover=Big, Output=JS).
- 등록 시 `title, author, publisher, isbn13, cover, categoryName, description`을 저장한다.
- 같은 isbn13이 이미 있으면 "이미 서재에 있어요"로 막는다. 직접 입력 책은 제목+저자가 같으면 경고만 한다.

**책 상태 전이**

- WANT → READING: 책 상세에서 "읽기 시작" 버튼.
- READING → DONE: 완독 처리 흐름. 별점·한 줄·완독일을 받는다.
- DONE → READING: "다시 읽기" 버튼. 기존 별점·소감은 유지하고 완독 시 덮어쓴다.
- 카메라 홈의 책 선택 목록에는 READING 책만 보인다. WANT·DONE 책에 글귀를 남기려면 상태를 바꾼다.

**소감**

- 별점은 1~5 정수, 한 줄은 100자 제한. 둘 다 필수는 아니지만, 비우면 분석 품질이 떨어진다는 안내 한 줄을 둔다.

**삭제**

- 글귀 삭제는 길게 눌러 삭제, 되돌리기 스낵바 5초.
- 책 삭제는 상세 메뉴에서 확인 다이얼로그 후 삭제. 글귀·토론도 함께 삭제된다.

## AI 기능

AI 호출은 두 곳뿐이다: 분석·추천 버튼과 완독 후 토론. 둘 다 Anthropic Messages API를 앱에서 직접 호출하고, 사용자가 설정에 넣은 키를 쓴다.

**취향 분석·추천**

입력(1회 호출):

- DONE 책 전체: 제목, 저자, 카테고리, 별점, 한 줄, 완독일
- 글귀 전체: 책 제목 + 글귀 텍스트 + 페이지
- 최근 토론이 있으면 각 토론의 마지막 사용자 발언 3개

시스템 프롬프트 요지:

- 저장된 글귀를 핵심 근거로 삼아 "이 사람이 어떤 문장에 멈추는지"를 해석한다. 장르 통계는 보조로 한 문단만.
- 별점 높은 책과 낮은 책의 차이를 글귀·소감에서 찾아 말한다.
- 아직 안 읽은 책 5권을 추천한다. 이미 서재에 있는 제목(WANT 포함)은 제외한다. 각 추천에 "당신이 저장한 ___ 글귀와 닿아 있어서" 식의 한 줄 이유를 붙인다.
- 출력은 JSON만: `{"taste": "...", "recommendations": [{"title": "...", "author": "...", "reason": "..."}]}`. 마크다운 펜스 없이.

후처리:

- 추천 각 항목을 알라딘 ItemSearch(제목+저자)로 조회해 isbn13·표지·링크를 붙인다. 못 찾으면 표지 없이 제목·저자만 표시.
- 결과는 Analysis 테이블에 저장. 화면은 최신 1건을 보여주고 이전 기록은 접힌 목록으로.

**완독 후 토론**

- 시스템 프롬프트에 그 책의 제목·저자·소개글·별점·한 줄·글귀 전체를 넣고, 이 부분을 `cache_control: {type: ephemeral}`로 캐싱한다. 매 턴 메시지 배열 전체를 보내되 캐시된 접두부는 재과금되지 않는다.
- 역할: "책 친구". 먼저 질문 하나를 던지고, 사용자 답에 이어 꼬리 질문을 한다. 한 번에 질문 1개, 답변은 3~4문장 이내. 반박보다 "왜 그렇게 느꼈는지"를 끌어내는 쪽.
- 첫 메시지는 앱이 자동으로 요청한다(사용자 입력 없이). 예: 별점과 글귀 위치의 불일치, 한 줄 소감의 단어 하나를 짚는 질문.
- 사용자 20턴 도달 시 AI에게 "마무리해 달라"는 숨은 지시를 붙여 마지막 응답을 받고 입력창을 닫는다.
- `max_tokens`는 토론 400, 분석 2000.

**비용 통제**

- 모델 기본값은 Haiku 계열. 설정에서 Sonnet으로 바꿀 수 있게 한다.
- 호출은 항상 사용자 동작(버튼, 전송)으로만 시작한다.
- 네트워크 오류·키 오류는 사용자에게 보여주고 재시도 버튼을 둔다. 자동 재시도는 1회만.
- 설정 화면에 "이번 달 호출 횟수"를 단순 카운트로 표시한다.

## 백업

설정 화면의 버튼 두 개로 끝난다. 서버도, 자동 동기화도 없다.

- 내보내기: Book·Quote·Discussion·Analysis 전체를 JSON 하나로 직렬화해 Storage Access Framework로 저장 위치를 고르게 한다. 파일명 `reading-backup-YYYYMMDD.json`. 표지 이미지는 URL만 포함(사진 원본은 애초에 없음).
- 가져오기: 파일 선택 → 스키마 버전 확인 → "기존 데이터를 지우고 덮어쓸까요, 합칠까요?" 선택. 합치기는 isbn13 또는 제목+저자가 같은 책을 같은 책으로 보고 글귀를 추가한다.
- JSON 최상위에 `schemaVersion` 정수를 두고, DB 마이그레이션과 함께 올린다.
- API 키는 백업에 포함하지 않는다.

## 예외 처리

| 상황 | 동작 |
| --- | --- |
| OCR이 텍스트를 하나도 못 읽음 | "글자를 찾지 못했어요. 더 밝은 곳에서 다시 찍어 주세요" + 다시 찍기 버튼 |
| OCR 결과가 세로쓰기·표·그림 섞임 | 줄 단위 나열을 그대로 보여주고 사용자가 고른다. 자동 필터링은 하지 않음 |
| READING 책이 하나도 없는데 촬영 | 셔터 비활성, "읽는 중인 책을 먼저 등록하세요" 버튼 → 서재로 이동 |
| 알라딘 검색 결과 없음 | 직접 입력 폼으로 전환 |
| 알라딘 호출 한도 초과·오프라인 | 직접 입력 폼으로 전환, 표지·장르는 비움 |
| Anthropic 키 미입력 상태에서 분석·토론 시도 | 설정 화면으로 안내 |
| Anthropic 응답이 JSON 파싱 실패 | 펜스·앞뒤 텍스트 제거 후 재파싱, 그래도 실패하면 원문을 taste로 저장하고 추천은 비움 |
| 추천된 책이 알라딘에 없음 | 표지 없이 제목·저자·이유만 표시, 담기는 직접 입력 책으로 생성 |
| 토론 중 네트워크 끊김 | 사용자 메시지는 로컬에 보관, 재전송 버튼 |
| 앱 강제 종료 중 토론 | Discussion은 매 턴 저장되므로 재진입 시 이어서 가능 |
| 가져오기 파일의 schemaVersion이 앱보다 높음 | 가져오기 거부, 앱 업데이트 안내 |

## 범위 밖

이번 버전에서 만들지 않는 것. 요청이 와도 사용자 확인 없이 추가하지 않는다.

- 로그인, 계정, 서버, 클라우드 자동 동기화
- iOS, 태블릿 전용 레이아웃
- 전자책 하이라이트 가져오기(밀리·리디·킨들)
- 사진 원본 보관, 밑줄 자동 감지
- 읽은 기간(시작일), 독서 습관 통계, 독서 목표
- 다른 사람과 공유, SNS 내보내기
- 토론 음성 입력, 증분 분석·샘플링 같은 토큰 절약

추후 후보: 토론 요약 후 이어가기, 글귀 검색, 위젯에서 바로 촬영.

## 클로드 코드 작업 순서

글귀 저장이 핵심이므로 그것부터 동작하게 만들고, AI는 맨 뒤에 붙인다. 각 단계는 실제 폰에서 확인한 뒤 다음으로 넘어간다.

1. 프로젝트 생성, Room 스키마(4테이블), 서재 화면과 직접 입력으로 책 등록·상태 변경
2. CameraX + ML Kit OCR + 문장 선택 화면 + 페이지 번호 자동 인식. 첫 화면을 카메라로. 여기까지가 MVP
3. 알라딘 검색 등록, 표지 캐시, 중복 체크
4. 완독 처리 화면(별점·한 줄·완독일), 책 상세의 글귀 목록
5. 설정 화면: API 키 저장, JSON 내보내기/가져오기
6. 분석·추천: Anthropic 호출, JSON 파싱, 알라딘 후처리, 결과 저장과 화면
7. 완독 후 토론: 캐싱 적용, 20턴 제한, 저장과 재진입
8. 예외 처리 표 전체 점검, 오프라인 동작 확인

구현 전 확인할 것: 알라딘 TTB 키 발급, Anthropic 키 발급, 현재 모델명과 단가, ML Kit 한국어 모델이 번들인지 다운로드 방식인지.
