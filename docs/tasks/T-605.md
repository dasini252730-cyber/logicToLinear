## 설명

추천 각 항목을 알라딘 ItemSearch(제목+저자)로 조회해 isbn13·coverUrl·aladinUrl을 붙인다. 못 찾으면 그 필드는 null. 5건 조회를 병렬로 처리하되 한도를 고려한다.

## 작업 브리핑

(2026-10-05, task-briefer 작성)

### 쉽게 말하면
Claude가 추천한 책 5권의 제목과 저자를 알라딘에서 검색해 표지 URL, ISBN, 알라딘 링크 같은 추가 정보를 붙인다. 만약 알라딘에서 찾지 못한 책이 있으면 그 필드를 비워 둔다. 5권을 동시에 요청해 빨리 처리한다.

### 주의할 점
- 5건 병렬 요청: `coroutineScope { launch { ... } launch { ... } ... }` 또는 `async`·`awaitAll()`. 순차 요청(2.5초 * 5 = 12.5초)보다 병렬(2.5초)이 훨씬 빠르다.
- 알라딘 일 호출 한도를 고려: T-301에서 확인한 한도가 있으면, enrichRecommendations에서는 이미 넘었을 가능성이 있으므로 오류를 받아도 정상. AladinResult.ApiError나 Network는 그 필드를 null로 두고 계속 진행.
- aladinUrl: 알라딘 ItemSearch 응답의 link 필드
- coverUrl: 알라딘 cover 필드. 이미지는 로컬 캐시하지 않음(요구사항 "사진 원본 저장 금지"). UI에서 Coil·Glide로 원격 로드.
- 반환 타입: suspend fun이면 T-606의 ViewModel에서 viewModelScope.launch로 호출 가능

### 완료 조건 체크 방법

- `testParallelExecution` (확인 필요): 5개 요청이 순차(12.5초 이상)가 아니라 병렬(2.5초)인지 프로파일링으로 확인 (수동 테스트 또는 타이머 테스트)

## 작업 메모

(2026-10-05)

- `data/ai/RecommendationEnricher(aladin: AladinSearch).enrich(list)`: 추천마다 `searchByTitle(제목)`을 `async`로 병렬 호출(5건). 결과에서 `pickMatch`가 저자 포함 → 제목 접두 일치 → 첫 항목 순으로 고르고 isbn13·cover→coverUrl·link→aladinUrl을 붙인다. 알라딘 `ApiError`·`Network`·`NoKey`·예외는 모두 "그대로 둔다"로 처리해 분석 전체가 실패하지 않는다.
- 알라딘 ItemSearch는 QueryType=Title만 쓰므로(T-301) "제목+저자" 조회는 제목으로 검색한 뒤 저자로 거른다. 이미 isbn13이 있는 항목은 다시 조회하지 않는다.
- 한도: 분석 1회에 5건. 알라딘 일 한도(수천 건) 대비 무시할 수준이라 직렬화하지 않았다.
