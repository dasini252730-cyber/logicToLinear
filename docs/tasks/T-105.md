## 작업 브리핑

2026-10-05 · task-briefer

### 쉽게 말하면

완독한 책에 대해 AI와 나눈 대화(Discussion)와 취향 분석 결과(Analysis)를 저장하는 두 엔티티와 쿼리 메서드들을 만든다. Discussion은 책마다 여러 개 가능하고, Analysis는 분석·추천 실행 이력을 독립적으로 쌓는다.

### 요구사항 원문에서

- `데이터 모델 > Discussion`: "id (Long PK), bookId (Long FK), messagesJson (String) - [{role, content, at}] 배열, 최대 40개(20턴), startedAt (Instant), endedAt (Instant?)" — Discussion 엔티티의 구조. 대화 내용은 JSON 문자열로 저장.
- `데이터 모델 > Analysis`: "id (Long PK), runAt (Instant), tasteText (String) - AI가 쓴 취향 해석 글, recommendationsJson (String) - [{title, author, reason, isbn13?, coverUrl?, aladinUrl?}], inputBookCount (Int), inputQuoteCount (Int)" — Analysis 엔티티의 구조. 추천 책 목록과 입력 데이터 현황을 함께 저장.
- `AI 기능 > 완독 후 토론`: "토론은 Discussion에 저장되고 책 상세에서 다시 볼 수 있다." — Discussion 저장 및 조회 시점
- `AI 기능 > 취향 분석·추천`: "결과는 Analysis 테이블에 저장. 화면은 최신 1건을 보여주고 이전 기록은 접힌 목록으로." — Analysis 저장 및 조회 순서

### 주의할 점

- Analysis는 bookId FK가 없음 (Book과 무관한 독립적 분석 이력)
- Discussion의 messagesJson은 JSON 문자열로 저장하되, 타입변환기나 직렬화는 별도 task에서 다룸
- upsert는 같은 id면 업데이트, 없으면 삽입 (Discussion이 재개될 때 사용)
- observeAllDesc는 최신 결과부터 보여주기 위해 runAt 내림차순 정렬
- Instant 필드는 TypeConverter 필요

### 완료 조건 체크 방법

- `두 엔티티 필드가 요구사항 표와 일치`: Discussion.kt, Analysis.kt 열어 @Entity 필드와 테이블 스키마 대조
- `DiscussionDao.observeByBook`: @Query("SELECT * FROM discussion WHERE bookId = :bookId") Flow 쿼리 확인
- `DiscussionDao.upsert`: @Upsert 메서드 또는 @Insert @Update 로직 확인
- `AnalysisDao.observeAllDesc`: @Query("SELECT * FROM analysis ORDER BY runAt DESC") Flow 쿼리 확인
- `AnalysisDao.insert`: @Insert 메서드 확인
