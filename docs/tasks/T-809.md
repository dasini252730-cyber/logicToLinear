## 설명

BookSearchEntry.onOpenSettings가 검색 위에 SettingsRoute를 navigate로 쌓는데 SettingsRoute는 top-level이라 하단 탭이 보인다. 거기서 탭을 누르면 navigateTopLevel의 popUpTo(시작 화면)가 검색 화면까지 걷어 입력하던 검색어가 사라진다(T-806 리뷰 경고 9, 기존 문제). 고치는 방법 후보: 설정으로 갈 때 navigateTopLevel(SETTINGS)로 통일하고 돌아올 길은 서재 → +로 두거나, 설정 화면이 검색 위에 쌓였을 때는 하단 탭을 숨긴다. 사용자 확인 후 결정.

### 쉽게 말하면
책을 검색하는 화면에서 설정으로 이동할 때 설정 화면이 검색 화면 위에 쌓인다. 그 상태에서 하단 탭을 누르면 검색 화면 전체가 사라져 입력 중이던 검색어를 잃게 되는 문제다. 이를 해결해 검색 화면의 상태를 보존하거나 네비게이션 흐름을 변경한다.

### 요구사항 원문에서
- `화면과 사용자 흐름 - 흐름 2 책 등록`: "서재 → + 버튼 → 검색창에 제목 입력" — 검색 화면이 핵심 진입점이며 사용자가 여기서 머물러야 함
- `예외 처리 - 도서 검색 인증키 미입력`: "책 검색을 쓰려면 설정에서 국립중앙도서관 인증키를 입력하세요" — 검색 화면에서 설정으로의 이동이 정상적인 사용 경로
- `예외 처리 - 도서 검색 인증키 무효`: "국립중앙도서관 인증키가 올바르지 않아요. 설정에서 다시 입력하세요" — 마찬가지로 검색 중 설정으로 가는 것이 자연스러운 흐름

### 선행 작업이 남긴 것
선행 없음. 다만 T-806 리뷰 경고 9에서 지적된 기존 문제: 화면 구조 변경(T-806, 검토 중) 후 검색 위에 설정을 쌓는 방식의 문제 발생.

### 주의할 점
- **사용자 확인 필요**: task 설명에 두 가지 해결 방법 후보가 제시되었으나 선택되지 않음
  1. navigateTopLevel(SETTINGS)로 통일하고 설정에서 돌아오는 길을 서재 → +로 변경
  2. 검색 화면 위에 설정이 쌓였을 때 하단 탭 자체를 숨기기
- AppNavigation.kt의 navigateTopLevel 함수(132-138줄)는 `popUpTo(graph.findStartDestination().id)`로 서재까지 백스택을 비우는 구조 → 검색 화면 위의 모든 라우트를 걷어낸다
- BookSearchEntry의 NeedsKey 컴포저블(188-207줄 예상)에서 "설정 열기" 버튼이 onOpenSettings를 호출함
- 요구사항의 예외 처리 표에서 키 무효/미입력 시 사용자를 "설정에서 다시 입력하세요"로 안내하는 흐름을 깨뜨리지 않아야 함
