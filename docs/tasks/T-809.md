## 설명

BookSearchEntry.onOpenSettings가 검색 위에 SettingsRoute를 navigate로 쌓는데 SettingsRoute는 top-level이라 하단 탭이 보인다. 거기서 탭을 누르면 navigateTopLevel의 popUpTo(시작 화면)가 검색 화면까지 걷어 입력하던 검색어가 사라진다(T-806 리뷰 경고 9, 기존 문제). 고치는 방법 후보: 설정으로 갈 때 navigateTopLevel(SETTINGS)로 통일하고 돌아올 길은 서재 → +로 두거나, 설정 화면이 검색 위에 쌓였을 때는 하단 탭을 숨긴다. 사용자 확인 후 결정.

## 작업 메모

- 2026-10-21. 사용자 지시("백로그 보고 계속 진행")에 따라 두 후보 중 **후보 2(설정이 검색 위에 쌓였을 때 하단 탭 숨김)** 를 택했다. 사용자 확인은 아직 없다(아래 "사용자에게 묻는 것").
- 처음엔 후보 1(`navigateTopLevel(SETTINGS)` + 서재 `+`에서 `restoreState`로 복원)로 구현했으나 1차 적대적 리뷰 차단: Navigation 2.10.2 `executePopOperations`가 `popUpTo(서재){saveState}` 때 `backStackMap[서재 id]`에도 저장 스택을 매단다(서재 id가 아직 map에 없을 때, 즉 앱 시작 후 탭 전환을 한 적이 없을 때). 그 뒤 서재 탭의 `navigate(서재){restoreState}`가 검색 화면을 복원해 서재 대신 검색이 뜨고 탭이 사라진다. 탭 전환 이력에 따라 동작이 달라지는 구조라 폐기했다.
- 후보 2 구현: `SettingsRoute`를 `data class SettingsRoute(val overSearch: Boolean = false)`로. 검색의 "설정으로"는 `navigate(SettingsRoute(overSearch = true))`. `showBottomBar`는 top-level이어도 `overSearch`면 false. 그 설정 화면에는 상단 뒤로가기 버튼(`SettingsEntry(onBack)`)을 준다. 시스템 뒤로가기·상단 버튼 모두 `popBackStack`으로 검색(ViewModel 그대로, 검색어 유지)에 돌아온다. 탭이 없으니 탭 전환으로 검색 화면이 걷히는 경로 자체가 없다.
- 1차 리뷰 경고 1(키를 넣고 돌아와도 "키 없음" 안내가 그대로): `BookSearchEntry`에 `LifecycleEventEffect(ON_RESUME)` → `BookSearchViewModel.retryIfKeyWasMissing()`. `needsKey`·`keyInvalid`일 때만 같은 검색어로 재검색한다(첫 진입·정상 결과 뒤에는 아무 일도 없음, 테스트 2개). 책 검색은 AI 호출이 아니라 원칙 4와 무관.
- 1차 리뷰 경고 5(토론 → 설정 경로에 같은 saveState 문제): 범위 밖, **T-810**으로 분리.
- 1차 리뷰 경고 2·3·4(복원 상태 만료·프로세스 재시작·+ 두 번 탭)는 후보 1에만 해당해 후보 2 전환으로 사라짐.
- 네비게이션 자동 테스트: compose-ui-test·navigation-testing 의존성이 없어 추가하지 않음(T-303과 같은 사유). 실기기 확인 항목으로 남긴다.
