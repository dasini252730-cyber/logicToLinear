## 설명

{taste, recommendations[]}를 파싱한다. 실패 시 마크다운 펜스·앞뒤 텍스트를 제거해 재파싱하고, 그래도 실패하면 원문을 taste로 두고 recommendations는 빈 배열.

## 작업 브리핑

(2026-10-05, task-briefer 작성)

### 쉽게 말하면
Claude가 보낸 분석 결과는 JSON이어야 하는데, 가끔 JSON 앞뒤에 설명 문장이 붙거나 마크다운 펜스(```)가 포함될 수 있다. 이 작업은 그런 경우에도 JSON을 추출해 파싱하는 파서를 만드는 부분이다. 파싱에 완전히 실패하면 에러 메시지를 그대로 보여주고 추천은 비운다.

### 요구사항 원문에서
- `AI 기능 > 취향 분석·추천`: "출력은 JSON만: {\"taste\": \"...\", \"recommendations\": [{\"title\": \"...\", \"author\": \"...\", \"reason\": \"...\"}]}" — 기대 형식
- `예외 처리`: "Anthropic 응답이 JSON 파싱 실패 → 펜스·앞뒤 텍스트 제거 후 재파싱, 그래도 실패하면 원문을 taste로 저장하고 추천은 비움" — 정확한 폴백 전략

### 선행 작업이 남긴 것
- T-601: AnthropicClient가 API 응답 본문을 String으로 반환. parseAnalysis()는 이 String을 받는다.

### 주의할 점
- 파싱 순서: 1) 입력 문자열 그대로 Json.decodeFromString() 시도 / 2) 실패 시 마크다운 펜스(```json ... ```, 기타 ```...``` 포함) 제거 후 재시도 / 3) 실패 시 {, } 사이의 내용만 추출 후 재시도 (앞뒤 설명문 제거) / 4) 완전 실패 시 원문을 taste로, recommendations은 "[]"로
- recommendations 필드가 생략되거나 빈 배열이 올 수 있다. 이 경우 UI는 taste만 보이고 카드 영역을 숨긴다(T-607).
- JSON 구조: taste는 문자열, recommendations는 배열. 각 추천 항목은 title, author, reason 필수, isbn13, coverUrl, aladinUrl은 선택(null 가능).

### 완료 조건 체크 방법
- `testParseAnalysisNormal`: 정상 JSON 입력 시 파싱 성공, taste와 recommendations 필드 확인 (`./gradlew testDebugUnitTest`)
- `testParseAnalysisWithFences`: ```json {...} ``` 형태 입력 시 펜스 제거 후 파싱 성공 확인
- `testParseAnalysisWithNarration`: "분석 결과: {...}" 형태로 앞뒤 설명문이 있을 때 {, } 사이 추출 후 파싱 성공 확인
- `testParseAnalysisCompleteFailure`: 완전 실패 시 tasteText == 원문, recommendationsJson == "[]" 확인
