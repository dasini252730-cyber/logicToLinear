## 작업 브리핑

(2026-10-05, task-briefer 작성)

### 쉽게 말하면
서재 화면에서 책의 상태(읽는 중 / 읽고 싶음 / 다 읽음)를 3개 탭으로 나누어 보여준다. 각 탭에서는 해당 상태의 책만 목록으로 표시되고, 책의 표지 이미지가 없으면 제목의 첫 글자를 플레이스홀더 배경으로 사용한다. 빈 상태에서는 안내 문구와 + 버튼을 표시한다.

### 요구사항 원문에서
- `화면과 사용자 흐름 > 서재`: "책 목록, 상태별 탭(읽는 중 / 읽고 싶음 / 다 읽음)" — 3개 탭의 필수 구조
- `흐름 2: 책 등록`: "서재 → + 버튼" — 빈 상태에서 추가 버튼 필요
- `데이터 모델 > Book`: "status Enum WANT / READING / DONE" — 상태의 정의
- `확정된 결정`: "책 상태 읽고 싶음 / 읽는 중 / 다 읽음" — 상태 순서와 명칭 확정
- `.claude/rules/android.md` Compose 규칙: "XxxScreen(state, onEvent) 형태", "문자열은 strings.xml", ViewModel은 상태와 이벤트만 — 구조

### 선행 작업이 남긴 것

### 주의할 점
- 책을 탭했을 때의 상세 화면 네비게이션은 T-111에서 구현되므로, 여기서는 onBookTap 콜백을 ViewModel에서 받기만 할 것.
- 빈 상태(책이 없을 때)에 + 버튼을 보여주되, 그 버튼의 클릭 처리(책 검색 화면 진입)는 T-110에서 구현되므로, 여기서는 콜백 준비만.
- 표지 플레이스홀더는 제목의 첫 글자를 배경 위에 표시. coverUrl이 null인 경우의 UI 처리.
- T-109 완료 조건 중 "책을 탭하면 상세로 이동한다(상세는 T-111)"는 여기서 onBookTap 콜백을 정의하기만 하고, 실제 네비게이션은 T-111에서 진행.

### 완료 조건 체크 방법
- 탭 전환 시 해당 상태 책만 보인다: 데이터베이스에 읽는 중/읽고 싶음/다 읽음 책을 미리 추가한 후 탭을 전환해서 해당 상태의 책만 나타나는지 확인
- 책을 탭하면 상세로 이동한다: onBookTap 콜백이 정의되어 있고 로그나 테스트로 호출되는지 확인 (T-111에서 실제 네비게이션 구현)

## 작업 메모

(2026-10-05)

- `LibraryViewModel`: 선택 탭 `MutableStateFlow(READING)` → `flatMapLatest { repo.observeByStatus(it) }` → `LibraryUiState(tab, books, loaded)`. 탭 순서 `LIBRARY_TABS` = 읽는 중 / 읽고 싶음 / 다 읽음(요구사항 "서재").
- `LibraryEntry`(진입점, ViewModel 참조) → `LibraryScreen(state, onTabSelect, onBookClick, onAddClick)`. 표지는 제목 첫 글자 플레이스홀더(`CoverPlaceholder`, T-306에서 이미지 로딩으로 대체). 빈 상태 문구는 탭별로 다르고 READING 빈 상태만 "+ 버튼으로 등록하세요"를 안내한다. FAB(+)가 등록 화면으로 간다.
- `loaded`가 false인 동안에는 빈 문구를 보이지 않게 해 깜빡임을 막았다. 탭을 바꾸면 `onStart`로 `tab`이 먼저 바뀌어 탭 표시가 DB 응답을 기다리지 않는다(리뷰 경고 3). `stateIn`은 `Lazily`로 두어 화면을 떠났다 돌아와도 마지막 탭이 유지된다.
- 네비게이션 라우트 object `LibraryRoute`와 이름이 겹쳐 진입 컴포저블은 `LibraryEntry`로 했다(ui/book도 같은 `XxxEntry` 규약).
- 표지 플레이스홀더는 `ui/components/BookCover`로 옮겼고(상세와 공용), 첫 글자는 코드 포인트 단위로 떼어 이모지가 깨지지 않는다(리뷰 경고 4, `firstGlyph` 테스트).
- `@Preview`는 규칙대로 화면당 하나만 남겼다(리뷰 경고 8). 테스트 `LibraryViewModelTest`(탭 전환 시 해당 상태만, 빈 탭) 추가(리뷰 경고 2).
