### 쉽게 말하면
백업 파일의 JSON 구조를 정의하는 Kotlin 데이터 클래스와 함수를 만든다. 앱의 네 개 데이터 테이블(Book, Quote, Discussion, Analysis)을 BackupFile 모델 안 배열로 표현하고, kotlinx.serialization으로 JSON으로 변환할 수 있게 한다. API 키는 절대 포함하지 않고, Room 스키마 버전과 백업 JSON의 schemaVersion을 같은 상수에서 관리한다.

- `백업`: "내보내기: Book·Quote·Discussion·Analysis 전체를 JSON 하나로 직렬화해 (...) API 키는 백업에 포함하지 않는다." — BackupFile 구조와 엔티티→모델 매퍼 범위
- `데이터 모델`: "테이블 4개면 충분하다. Book 하나에 Quote·Discussion이 여러 개 매달리고..." — BackupFile 안의 배열 4개 정의
- `기술 스택`: "백업 = kotlinx.serialization → JSON 파일" — 직렬화 방식

### 주의할 점
- **schemaVersion은 AppDatabase의 DB_SCHEMA_VERSION을 그대로 쓴다**: `schemaVersion: Int = DB_SCHEMA_VERSION` 기본값 또는 초기값 설정 (T-502 단계에서는 초기값 1).
- **API 키 포함 금지**: BackupFile에 apiKey 필드가 없어야 하고, 매퍼도 SecretStore에 건드리지 않음. T-503(내보내기)에서는 저장된 JSON을 검증할 때 "apiKey" 문자가 없는지 확인할 것.
- **라운드트립 테스트**: 실제 엔티티 객체 하나를 DTO로 변환 → JSON으로 직렬화 → 역직렬화 → 비교. 모든 필드가 올바르게 변환되는지 확인.
- **요구사항 "마이그레이션 훅" (T-504)**: 이 task에서는 마이그레이션 함수를 구현하지 않음. schemaVersion을 read하기만 하고, 버전이 앱보다 높으면 T-504에서 거부함.

- 직렬화된 JSON의 키(최상위 필드 이름)가 "schemaVersion", "books", "quotes", "discussions", "analyses"인지 시뮬레이터/기기에서 저장 후 확인
