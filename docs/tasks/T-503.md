### 쉽게 말하면
설정 화면의 "내보내기" 버튼을 눌렀을 때, 시스템 파일 선택 화면(SAF)이 열려서 사용자가 저장 위치를 고르게 하고, 그곳에 오늘 날짜 형식의 파일명(reading-backup-YYYYMMDD.json)으로 백업 JSON을 저장한다. 저장 성공/실패를 토스트로 보여준다.

### 요구사항 원문에서
- `백업`: "내보내기: Book·Quote·Discussion·Analysis 전체를 JSON 하나로 직렬화해 Storage Access Framework로 저장 위치를 고르게 한다. 파일명 reading-backup-YYYYMMDD.json." — 파일명 규칙과 SAF 사용 방식
- `백업`: "표지 이미지는 URL만 포함(사진 원본은 애초에 없음)." — 백업에 들어갈 coverUrl 필드
- `백업`: "API 키는 백업에 포함하지 않는다." — BackupFile에 apiKey가 없어야 함 (T-502에서 확인)
- `예외 처리`: "가져오기 파일의 schemaVersion이 앱보다 높음 = 가져오기 거부, 앱 업데이트 안내" — T-504의 선행 작업이므로 이 task에서는 저장만 구현

### 선행 작업이 남긴 것

- T-501: SettingsScreen이 내보내기·가져오기 버튼을 가지고 있음 (또는 가질 예정)

### 주의할 점
- **파일명 규칙**: `reading-backup-YYYYMMDD.json`. 예: `reading-backup-20261005.json`. LocalDate.now()로 생성.
- **SAF 사용**: ActivityResultContracts.CreateDocument("application/json")로 사용자가 이름·위치를 입력할 수 있게 함. 또는 기본 이름을 제시하고 사용자가 원하면 변경할 수 있게.
- **저장소 권한**: minSdk 26이면 WRITE_EXTERNAL_STORAGE는 불필요 (SAF가 처리). 다만 build.gradle에 선언되었는지 확인.
- **apiKey 검증** (완료 조건): 저장 후 같은 파일을 읽어서 "apiKey" 문자열이 들어있지 않은지 테스트하거나, 시뮬레이터의 파일 시스템에서 직접 확인.
- **토스트**: "백업 저장됨" / "저장 실패" 정도. 파일명도 포함 가능 (요구사항 예외 처리에는 명시되지 않았으나 UX상 좋음).

### 완료 조건 체크 방법
- 설정 화면 "내보내기" 버튼 탭, 파일 선택 다이얼로그 열리는지 확인
- 저장 위치를 선택하고 기본 이름 또는 입력한 이름이 reading-backup-YYYYMMDD.json 규칙을 따르는지 확인
- 저장 후 "백업 저장됨" 토스트 표시 확인
- 저장된 파일을 텍스트 에디터나 grep으로 열어 "apiKey", "anthropic", "ttb" 등 민감한 문자열이 없는지 확인
