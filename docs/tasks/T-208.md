### 주의할 점

- 상태 관리:
  - `pageText: String` (사용자 입력, 빈 문자열 = null)
  - `pageCandidates: List<String>` (T-207 결과)
  - `autoFilled: Boolean` (후보 1개일 때만 true)
- 우선순위: 직접 입력 값이 없으면 후보 사용, 둘 다 없으면 null
- UI 상태:
  - 후보 0개: 빈 TextField만 (입력 필드)
  - 후보 1개: 자동 채움 (disabled 상태로 표시 가능)
  - 후보 2개 이상: 빈 TextField + 후보 칩들
- 입력 유효성: 숫자만 입력 받되, 1~4자리 제한은 T-207과 동일 (또는 여기서도 제한)
- 건너뛰기: page = null인 상태로 저장 허용 (Quote.page는 nullable)
- 토스트 메시지: page != null이면 "저장됨 (p.${page})", null이면 "저장됨"
- T-206·T-208은 같은 화면(QuoteEditScreen) 내에서 동시에 구성되므로, 이 작업은 T-206 완료 후 진행
- 칩 탭: 칩을 탭하면 해당 값이 TextField에 자동으로 입력되어야 함
- 직접 입력 후 칩 탭: 직접 입력 값이 유지되고, 칩은 선택 표시만 됨 (우선순위 명확화)

### 완료 조건 체크 방법

- 후보 1개일 때 자동 채움이 즉시 반영되는지 확인
- 후보 2개 이상일 때 칩이 표시되고 탭 가능한지 확인
- 숫자 키패드로 입력했을 때 직접 입력 값이 후보보다 우선인지 확인
- page = null인 상태(빈 입력)로 저장 가능한지 확인
- 토스트 메시지 "저장됨 (p.123)" 또는 "저장됨"이 page 값에 따라 올바르게 표시되는지 확인
- UI 테스트 또는 수동 테스트로 후보 선택·직접 입력·건너뛰기의 모든 시나리오 검증

## 작업 메모

(2026-10-05)

- `SelectViewModel.initialState`: 후보 1개면 `pageInput`에 자동 채움(`pageAutoFilled = true`, 칸 아래 "자동 인식" 표시), 2개 이상이면 빈 칸 + 칩, 0개면 빈 칸. 칩(`PageChips`)은 후보가 하나라도 있으면 보여서 자동 채운 값을 지웠다가 되돌릴 수 있고(리뷰 질문 3), 후보가 많으면 가로 스크롤한다(리뷰 경고 1). 칩은 페이지 칸 아래 줄에 둔다.
- 직접 입력(`onPageChange`)은 숫자만 4자리까지 받고 `pageAutoFilled`를 false로 바꾼다. 칩 탭도 같은 경로를 타므로 "직접 입력이 우선"이 자연히 성립한다(마지막에 사용자가 넣은 값이 저장됨). 자동 채움 값도 그대로 고칠 수 있다(비활성 칸으로 두지 않았다).
- 비워 두고 저장하면 `page = null`(건너뛰기 허용). 키보드는 `KeyboardType.Number`.
- 테스트: 후보 1개 자동 채움, 후보 2개 빈 칸+칩, 직접 입력 우선·숫자 필터, 페이지 비움 저장.
