## 작업 브리핑

(2026-10-05, task-briefer 작성)

### 쉽게 말하면
Jetpack Navigation Compose로 앱의 라우트 그래프를 정의하고, 하단 탭 3개(서재 / 분석·추천 / 설정)로 화면 간 이동을 구현한다. 카메라(홈) 라우트는 2단계까지 PlaceholderScreen으로 임시 표시한다. 현재 MainActivity의 자리 표시 화면은 삭제된다.

### 요구사항 원문에서
- `화면과 사용자 흐름`: "화면은 6개다...카메라(홈) 글귀 촬영...하단 탭이나 책 상세에서 들어간다...서재 / 분석·추천 / 설정" — 하단 탭 3개와 홈 라우트의 필수 구조
- `설계 원칙`: "앱을 열면 2초 안에 카메라가 떠야 한다" — 성능과 홈 라우트의 중요성
- `기술 스택`: "Jetpack Compose로 만들고...로컬 DB는 Room" — Navigation Compose 2.10.2 사용
- `.claude/rules/android.md` Compose 규칙: "XxxScreen(state, onEvent) 형태로 상태를 받고 이벤트를 올린다...라우트 상수와 NavHost" — 구조

### 선행 작업이 남긴 것
- T-107: AppContainer (Application 클래스의 수동 DI 컨테이너), BookRepository, ViewModel Factory(CreationExtras 확장)가 준비된다.

### 주의할 점
- MainActivity의 enableEdgeToEdge() 설정은 유지. T-108 메모에서 "Scaffold 또는 WindowInsets.safeDrawing 패딩으로 상태바·내비바 겹침을 처리할 것" — 각 화면 구현 시 고려할 사항이고, 이 task에서는 HomeScreen 임시 화면에서 최소한 보여줄 것.
- 홈 라우트가 실제 CameraX로 바뀌는 것은 T-201 이후이므로, 여기서는 PlaceholderScreen과 같은 수준의 임시 화면으로 충분.
- 라우트 상수는 하나의 파일(Routes.kt)에 모여 있어야 "완료 조건: 라우트 상수가 한 파일에 모여 있다"를 만족.

- 라우트 상수가 한 파일에 모여 있다: Routes.kt에 Home, Library, Analysis, Settings 상수가 모두 정의되어 있는지 확인
