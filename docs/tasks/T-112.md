### 쉽게 말하면

책 상세 화면의 메뉴에서 "삭제" 옵션을 추가한다. 사용자가 삭제를 선택하면 확인 다이얼로그를 띄워서 "이 책과 관련된 글귀, 토론이 함께 삭제됩니다"라고 경고한 후, 확인을 받아야 실제로 삭제한다. 삭제 후에는 서재로 돌아간다.

- 제품 원칙 "사용자 노출 문구는 요구사항 원문 그대로 써야 한다" — 다이얼로그 메시지는 정확히 일치

### 주의할 점

- 확인 다이얼로그는 필수. "지우기 전에 한 번 더 확인" 패턴 준수.
- 다이얼로그 메시지에 "이 책의 글귀와 토론도 함께 삭제됩니다" 등의 안내를 포함. 사용자가 부작용을 이해하고 동의.
- Book의 CASCADE 삭제는 Room의 외래키 제약으로 자동 처리. Quote와 Discussion의 bookId가 Book.id를 참조하고 onDelete = ForeignKey.CASCADE로 설정되어 있으면, BookRepository의 delete() 호출 시 자식 테이블 행도 함께 삭제됨.
- 삭제 후 네비게이션: popBackStack() 또는 navigate(Routes.Library)로 서재 화면으로 돌아가기. 서재 화면의 관찰 데이터(Flow 또는 LiveData)가 자동으로 갱신되므로 삭제된 책이 사라짐.
- 삭제 성공 후 토스트나 스낵바로 "삭제됨" 안내 (선택사항이지만 사용자 경험 개선).

### 완료 조건 체크 방법

- 확인 없이 삭제 안 됨: BookDetailScreen의 메뉴에서 삭제 옵션 탭, 다이얼로그가 띄워지는지 확인, "취소" 버튼 클릭 후 화면이 유지되는지 확인
- Quote·Discussion 함께 삭제: 어떤 책을 선택해 글귀를 몇 개 저장 후, 그 책의 상세에서 삭제 → 확인 → 서재로 돌아가 다시 그 책 상세로 들어감 → 글귀 목록이 비어 있는지 확인 (T-114 글귀 목록 구현 후 정확히 확인 가능. 현 단계선 DB 직접 조회로 확인: adb shell sqlite3 /data/data/.../reading.db "SELECT * FROM Quote WHERE bookId = ?")
