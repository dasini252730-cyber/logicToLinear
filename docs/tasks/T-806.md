### 주의할 점
- **2초 시작 원칙**: 탭 추가로 인한 초기화 성능 저하가 없어야 함. 카메라 탭은 TopLevelRoute에 추가되지만 popUpTo(startDestination)로 홈으로 간다는 점에서 성능상 문제는 없어야 함.
- **탭 순서와 아이콘**: 현재 task 설명에 "탭 순서·아이콘은 사용자 확인"이라고 있음. 아이콘 선택(예: CameraX, PhotoCamera 등)은 구현 후 사용자 확인 필요. 맨 앞 위치는 확정.
- **책 상세에서 글귀 찍기**: 그 책을 "읽는 중"으로 맞춘 후 홈으로 돌아갈 때, 홈의 기본 선택 책이 바뀌려면 lastQuoteAt을 갱신해야 할 수도 있음 (확인 필요).
- **네비게이션**: BookDetailScreen에서 홈으로 돌아가는 경로는 `navController.navigate(HomeRoute) { popUpTo(...) }` 형태. 이미 있는 onBack 콜백과 구분되므로 새 콜백이 필요.
- **상한 확인**: BookDetailViewModel 194줄이지만 상한이 200줄이므로 기능 추가 시 여유가 적음. 로직이 복잡하면 분리 계획 검토.

### 완료 조건 체크 방법
- 서재·분석·설정 화면에서 하단 탭 카메라 아이콘이 보이는지 → 누르면 홈으로 가는지
- 홈 화면에서 카메라 탭이 선택 상태(강조)로 보이는지
- 앱 냉 시작 시간을 재서 2초 이하인지 (실기기 또는 에뮬 측정)
- 책 상세 화면의 글귀 목록 하단(또는 헤더)에 '글귀 찍기' 버튼이 있는지
- 그 버튼 클릭 후 홈에서 그 책이 상단에 선택되어 있는지, 카메라가 떠 있는지

- 배경: 실기기 확인 중 사용자가 책 상세·토론 화면에서 카메라로 돌아가는 길을 못 찾았다. 기존 구조는 하단 탭 3개(서재·분석·추천·설정)뿐이고 홈은 시스템 뒤로가기로만 갔다.
- 설계: `TopLevelRoute`에 `CAMERA(HomeRoute)`를 맨 앞에 추가. 책 상세 "글귀 찍기"는 홈 백스택 엔트리의 `SavedStateHandle`에 `HOME_CAPTURE_BOOK_KEY`로 책 id를 넣고 `popBackStack<HomeRoute>`로 홈까지 팝한다. `HomeEntry`는 그 값을 받으면 `chooseBook`을 부르고 **즉시 키를 지워** 일회성으로 만든다. READING이 아닌 id는 `HomeViewModel`이 기본 책으로 되돌린다(기존 `HomeViewModelTest.고른_책이_READING에서_빠지면_기본_선택으로_돌아간다`가 이 폴백을 덮는다).
- 처음에는 `HomeRoute(bookId)` 라우트 인자로 넘겼으나 리뷰 차단: 인자는 홈 엔트리가 사는 동안 남아 있어 문장 선택 화면에서 돌아오거나 회전할 때 `LaunchedEffect`가 다시 돌아 사용자가 선택기로 바꾼 책을 덮어쓴다(글귀가 엉뚱한 책에 저장됨). SavedStateHandle 일회성 값으로 바꿔 해결했고, 홈 엔트리·ViewModel·카메라 바인딩도 재생성되지 않는다.
- 탭 전환은 기존 `navigateTopLevel`을 그대로 쓴다. 카메라 탭은 시작 목적지라 `popUpTo(start)`로 홈이 드러나고 `launchSingleTop`이 홈을 다시 쌓지 않는다. 글귀 찍기 뒤 뒤로가기는 탭 전환 때와 같이 앱을 나간다(상세로 돌아가지 않음). 상세로 돌아가려면 서재 탭.
- "글귀 찍기" 버튼은 READING 책에서만 보인다(요구사항 "책 상태 전이": 글귀는 READING 책에만). WANT는 "읽기 시작", DONE은 "다시 읽기"가 같은 자리에 있어 상태를 바꾸면 버튼이 나타난다.
- 브리핑은 `BookDetailViewModel` 수정을 예상했지만 ViewModel 상태가 필요 없어(책 id만 콜백으로 넘김) 건드리지 않았다. 카메라 아이콘 `Icons.Filled.PhotoCamera`는 material-icons-core에 없어 extended 의존성 대신 `res/drawable/ic_photo_camera.xml` 벡터를 두었다.
