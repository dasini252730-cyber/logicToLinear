### 주의할 점
- **비표준 JSON**: 알라딘 `Output=JS` 응답은 표준 JSON이 아닐 수 있다 (끝에 세미콜론이나 추가 문자). 파싱 전에 문자열 정리가 필요할 수 있다. (예: regex로 유효한 JSON 범위만 추출)
- **TTB 키**: 요구사항에서 "TTB 키 필요(무료, 일 호출 한도 있음)"이라고 했으므로, 키는 `SecretStore`에서 읽어야 한다. 코드에 하드코딩하지 않을 것.
- **호출 한도**: "알라딘 호출 한도 초과·오프라인 | 직접 입력 폼으로 전환, 표지·장르는 비움" (요구사항 예외 처리 250-251줄) — 이건 T-302(검색 UI)에서 처리하지만, 이 task에서도 오류 타입을 명확히 해두면 좋다.

## 작업 메모

(2026-10-05)

- 의존성(T-006 결정): Retrofit 3.0.0, `converter-kotlinx-serialization` 3.0.0, OkHttp 5.5.0, 테스트용 `mockwebserver3` 5.5.0.
- `data/remote/aladin/AladinApi`: `GET ttb/api/ItemSearch.aspx`에 요구사항 파라미터(Query=제목, QueryType=Title, MaxResults=10, Cover=Big, output=js) + `Version=20131101`(이 버전부터 output=js가 표준 JSON). DTO `AladinSearchResponse(totalResults, item, errorCode, errorMessage)`, `AladinItem`(저장 필드 7개 + link). `Json { ignoreUnknownKeys; coerceInputValues; isLenient }`.
- `AladinClient.searchByTitle(title)`: TTB 키를 호출 직전 `SecretStore`에서 읽어 없으면 `NoKey`, 빈 검색어는 호출 없이 `Empty`. 응답은 `Found`/`Empty`/`ApiError(code, message)`/`Network(cause)` sealed 결과로 돌려 UI(T-303~T-305)가 분기한다. HTTP 오류·직렬화 오류도 `Network`로 묶어 직접 입력 폼으로 보낸다.
- 타임아웃 connect 10초, read 15초. `AppContainer.aladinClient`(lazy).
- 테스트 `AladinClientTest` 6개(MockWebServer): 필드 7개 파싱 + 요청 파라미터 검증, 빈 결과, 오류 코드, 키 없음(호출 0), 빈 검색어(호출 0), 소켓 끊김·503.
- 적대적 리뷰 반영(차단 1 / 경고 5): `AladinJsonCleanupInterceptor`가 끝 세미콜론·`callback(...)` 래퍼를 벗겨 표준 JSON으로 만든 뒤 컨버터에 넘긴다(순수 함수 `cleanAladinJson` + MockWebServer 테스트). `callTimeout` 20초 추가. 요구사항 외 파라미터는 `Version` 하나만 남겼고 요청 파라미터 집합을 테스트로 고정했다. ViewModel이 클라이언트를 직접 쓰지 않도록 `BookRepository.searchAladin`을 거친다(`aladinClient`는 AppContainer 내부 private). null 필드 강제 테스트 추가. 취소 전파 테스트는 MockWebServer로 결정적으로 만들기 어려워 코드 검토로 대신한다.
- 알라딘 일 호출 한도 초과 시 응답 형태는 공식 문서에 명확하지 않다. errorCode가 오면 `ApiError`, 아니면 `Network`로 어차피 직접 입력 폼으로 넘어가므로 동작은 같다. T-307 실기기 확인 때 실제 응답을 기록한다.
