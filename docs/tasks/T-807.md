## 설명

실기기 확인(2026-10-05)에서 사용자가 'OCR이 너무 부정확하다'고 보고. 저장된 글귀 예: '대전은 바로 밈요섭고ㅓ'(p.123). 당시 프리뷰가 매우 어두웠음(저조도). 코드 점검 결과 후보: (1) CameraController의 ImageCapture가 CAPTURE_MODE_MINIMIZE_LATENCY라 노이즈·블러가 큼 → CAPTURE_MODE_MAXIMIZE_QUALITY로 바꾼다. (2) 촬영 직전 초점·노출 고정이 없음 → 화면 중앙 FocusMeteringAction(AF+AE)을 걸고 완료를 기다린 뒤 takePicture. (3) 저조도 대응 → 플래시 자동(FLASH_MODE_AUTO) 또는 밝기 안내 문구('글자를 찾지 못했어요. 더 밝은 곳에서 다시 찍어 주세요'는 이미 있음, 인식은 됐지만 틀린 경우에는 안내가 없음). (4) 해상도: ResolutionSelector 미지정(기본 최대)이라 유지. KoreanTextRecognizerOptions는 이미 사용 중. 각 변경 뒤 같은 페이지를 같은 조건에서 5회 찍어 전후를 비교해 기록한다.

### 쉽게 말하면
실기기에서 사용자가 보고한 OCR 오류('대전은 바로 밈요섭고ㅓ')를 저조도·블러·초점 미고정이 원인으로 판단하고, 촬영 모드를 품질 우선으로 바꾸고 촬영 직전 초점·노출을 고정한 뒤 5회씩 촬영해 개선 효과를 기록한다.

- `흐름 1: 글귀 저장`: "2. 셔터 → ML Kit OCR 실행 (로딩 1초 내외). 3. 문장 선택 화면" — OCR 입력 이미지의 품질이 직결된다
- `설계 원칙`: "앱을 열면 2초 안에 카메라가 떠야 한다" — 촬영 지연 증가 추적 필요
- `설계 원칙`: "사진 원본은 저장하지 않는다. OCR 후 비트맵은 메모리에서 폐기하고 추출된 텍스트만 저장한다" — 품질 개선은 온디바이스 OCR 입력 개선만
- `예외 처리`: "OCR이 텍스트를 하나도 못 읽음: '글자를 찾지 못했어요. 더 밝은 곳에서 다시 찍어 주세요'" — 저조도 안내는 이미 있음, 잘못 인식한 경우 안내 없음
- `기술 스택 > 카메라`: "CameraX | 촬영 후 비트맵을 OCR에 넘기고 사진은 폐기"

### 주의할 점
- **CameraX API 의존성**: `Camera.startFocusAndMetering(FocusMeteringAction)`을 쓰려면 `bindToLifecycle`이 반환하는 Camera 객체가 필요. 현재 CameraController.bind()는 카메라 객체를 저장하지 않으므로 수정 필요 (확인 필요)
- **촬영 지연 추적**: CAPTURE_MODE_MAXIMIZE_QUALITY로 변경하면 처리 시간이 늘 수 있음. 완료 조건 "촬영→문장 선택 화면까지 체감 지연 3초 이내"를 검증해야 함
- **사진 원본 저장 원칙 준수**: 촬영 최적화는 CameraController 내에서만, ImageProxy → Bitmap 변환 이후 단계는 건드리지 않음
- **예외 처리**: 저조도 감지 및 안내는 이 task 범위에서 구현하지 않음 (요구사항에는 "글자 못 찾음"만 있고 "틀린 경우" 안내는 없음)
- **단위 테스트**: HomeViewModelTest는 촬영하지 않으므로 CameraX 변경이 영향을 주지 않음. 기존 테스트 통과 확인
- **실기기 환경**: 삼성 SM-S942N (Android 16, API 36), debug 빌드
