### 쉽게 말하면

이 앱이 데이터를 저장(Room DB), 여러 화면으로 네비게이션, 사용자 입력을 JSON으로 변환(serialization)하고, 데이터 로딩 같은 오래 걸리는 작업을 백그라운드에서 처리(Coroutines)하기 위해 필요한 라이브러리들을 Gradle 버전 카탈로그에 등록한다. 이렇게 하면 다음 단계들이 이 라이브러리들을 쉽게 쓸 수 있다.

### 요구사항 원문에서

- `기술 스택`: "로컬 DB | Room (SQLite)" — SQLite를 간편하게 쓰기 위해 Room 라이브러리와 코드 생성(KSP) 도구가 필요하다.
- `기술 스택`: "Kotlin, Jetpack Compose로 만들고" — ViewModel은 화면의 상태를 관리하는 Jetpack Compose 표준 패턴이다.
- `기술 스택`: "백업 | kotlinx.serialization → JSON 파일" — Kotlin 객체를 JSON으로 직렬화하려면 이 라이브러리가 필요하다.
- `기술 스택`의 화면 표에서 "Compose Navigation" — 6개 화면 사이를 이동하려면 Navigation 라이브러리가 필요하다.
- `데이터 모델`: 4개 테이블(Book, Quote, Discussion, Analysis) — Room과 Coroutines로 DB 접근을 구현한다.

### 주의할 점

- **KSP와 Kotlin 버전**: Kotlin 2.4.20에 맞는 KSP 2.3.12를 쓴다 (T-101 작업 메모에서 확인). KSP는 Kotlin 메이저.마이너.패치 중 마이너 기준으로 쌍을 이루므로, Kotlin 버전을 올리면 KSP도 올려야 한다.
- **Lifecycle과 Compose**: Compose BOM 2026.09.00이 이미 lifecycle 2.10.0을 끌어오는데, T-101 주석에서 "T-107에서 BOM 관리로 추가"라고 했다. 따라서 이 단계에서는 lifecycle을 **명시적으로 선언하지 않고**, 다른 라이브러리의 BOM 또는 transitive 의존성으로 받아들인다.
- **Coroutines 버전**: Compose와 호환되려면 최신 stable 1.11.0 이상을 써야 한다 (T-101 메모에서 확인).
- **완료 조건**: assembleDebug 성공하면, 앱이 이 라이브러리들을 사용할 준비가 된 것이다. 하지만 실제로 Room·Navigation·ViewModel 코드는 아직 없으므로(T-103 이후), 빌드는 통과하되 이 라이브러리들을 쓰는 컴포넌트는 없는 상태다.

## 작업 메모

(2026-10-05)

- 추가한 버전: lifecycle 2.11.0, room 2.8.5, ksp 2.3.12, navigation 2.10.2, kotlinx-serialization 1.11.0, coroutines 1.11.0. 모두 2026-10-05 Google Maven / Maven Central 안정 최신(T-101 메모에서 확인).
- 플러그인 3개 추가: `org.jetbrains.kotlin.plugin.serialization`(Kotlin 버전과 동일), `com.google.devtools.ksp`, `androidx.room`(schemaDirectory를 `app/schemas`로). 루트에는 `apply false`, app에 적용.
- lifecycle은 Compose BOM이 관리하지 않는다. `compose-bom-2026.09.00.pom`을 받아 `lifecycle` 아티팩트가 없음을 확인했고 버전을 명시했다(T-101 리뷰 경고 3의 전제가 틀렸음).
- Room 2.7+는 `room-ktx`가 `room-runtime`에 합쳐져 runtime 하나만 넣었다. 테스트용으로 `room-testing`(androidTest), `kotlinx-coroutines-test`(test)를 넣었다.
- 의존성만 넣은 시점의 `./gradlew lintDebug assembleDebug testDebugUnitTest` 통과(2분 30초, 다운로드 포함), lint 0건. 그 직후 T-103~T-106(Room 엔티티·DB)을 같은 트리에서 이어서 구현했으므로 최종 커밋에는 KSP 산출물(`app/schemas/.../1.json`)이 함께 들어간다.
- **테스트 인프라 결정(리뷰 질문 1)**: Room 테스트는 Robolectric 4.17(`testImplementation`)로 JVM에서 돌린다. 실기기(T-005)가 아직 없어 androidTest만으로는 DB 테스트를 돌릴 수 없고, hook의 `testDebugUnitTest` 검증에 포함되기 때문이다. `room-testing`도 test 소스셋으로 옮겨 Migration 테스트가 같은 경로를 쓰게 했다. `androidx.test:core-ktx`는 `ApplicationProvider`용. SDK 37 이미지가 JDK 21에서 `FileDescriptor` 반사 오류를 내 `src/test/resources/robolectric.properties`로 sdk=34 고정.
- **Instant 정밀도(리뷰 경고 4)**: Converters가 epoch 밀리초로 저장하는데 `Instant.now()`는 마이크로초여서 저장 전후 값이 달라질 수 있었다. `data/db/DbTime.kt`의 `nowMillis()`를 엔티티 기본값으로 써서 맞췄다.
- CameraX·ML Kit·HTTP·security-crypto·Coil은 각 단계(T-201, T-203, T-301, T-302, T-306)에서 추가한다.
- 적대적 리뷰 1차: 차단 3(테스트 실패 → sdk=34로 해소 / 뒤 task 산출물 혼재 → 백로그 상태를 T-103~T-106으로 진행시켜 정리 / 문서 불일치 → 이 메모 갱신), 경고 4(테스트 인프라 결정 기록, 주석 모순 수정, schemaDirectory는 T-106과 함께 검증됨, Instant 정밀도 수정).
