### 주의할 점
- **FK 제약 조건**: T-404 메모에 따르면 되돌리기 스낵바가 떠 있는 5초 동안 책이 삭제되면 `QuoteDao.insert(saved)`가 `SQLiteConstraintException(FK)`을 던진다. `restore()` 호출 전에 책 존재를 확인하고 없으면 스낵바를 조용히 닫을 것. (현재 `QuoteRepository.restore()`에서 `bookDao.getById()`로 확인하고 false 반환)
- **테스트**: '책 삭제 후 되돌리기' 케이스를 테스트에 추가할 것

### 완료 조건 체크 방법
- 글귀를 길게 눌러 삭제되는지 확인 → 스낵바의 '되돌리기' 버튼 표시 여부 확인
- 되돌리기 버튼 탭 시 글귀가 원래 자리로 돌아오는지 확인
- 5초 대기 후 스낵바 사라지면 DB에서 삭제되었는지 확인 (수동 테스트 또는 단위 테스트)

## 작업 메모

(2026-10-05)

- 글귀 항목을 `combinedClickable(onLongClick)`으로 길게 누르면 `BookDetailViewModel.deleteQuote`가 DB에서 바로 지우고 `undoCandidate`에 둔다. 화면은 `SnackbarHost`에 "글귀를 삭제했어요" + "되돌리기"를 `withTimeoutOrNull(5_000)`로 **정확히 5초** 띄운다(Material 기본 길이 대신).
- 되돌리기 탭 → `undoDelete()` → `QuoteRepository.restore(quote)`: 같은 id로 다시 insert. 그 사이 책이 지워졌으면 `restore`가 false를 돌려주고 조용히 끝난다(백로그 인계 메모 반영, `QuoteRepositoryTest.책이_지워진_뒤_되돌리기는_실패를_알리고_예외를_내지_않는다`).
- 5초는 ViewModel이 센다(`deleteQuote`가 `delay(UNDO_WINDOW_MS)` 뒤 후보를 비움). 화면은 후보가 있는 동안만 스낵바를 띄우고, 스낵바를 밀어 치우면 `clearUndo()`. DB에서는 이미 지워져 있으므로 "5초 후 완전 삭제" 조건은 성립한다.
- 테스트 `BookDetailViewModelTest`: 삭제 즉시 목록에서 사라지고 되돌리기로 같은 id 복구, 시간 초과 후 DB에 남지 않음.

- 적대적 리뷰 반영(2026-10-05): 타이머가 화면 `LaunchedEffect`에 있어 회전마다 5초가 다시 흐르던 것을 ViewModel로 옮겼다. 5초 안에 다른 글귀를 지우면 앞 후보는 되돌릴 수 없다(스낵바 하나만 두는 일반적인 동작, 문서화). `QuoteRepository.delete`가 `deleteAndTouchBook`으로 책 `lastQuoteAt`을 남은 글귀의 MAX로 다시 계산한다(`restore`도 같은 경로). 테스트 `최근_글귀를_지우면_lastQuoteAt이_이전_글귀_시각으로_돌아가고_모두_지우면_null`.
