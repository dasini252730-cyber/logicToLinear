## 설명

사용자 메시지와 AI 응답을 각각 저장 즉시 messagesJson에 반영한다. 책 상세의 토론 목록에서 진행 중 토론을 열면 이어서 대화할 수 있다.

## 완료 조건

- [ ] 앱 강제 종료 후 재진입 시 마지막 메시지까지 보인다
- [ ] endedAt이 null인 토론은 입력창이 열려 있다

## 작업 브리핑

(2026-10-05, task-briefer 작성)

### 쉽게 말하면
사용자가 메시지를 보낼 때마다 그 메시지와 Claude의 답변을 즉시 데이터베이스에 저장한다. 이렇게 하면 앱이 갑자기 꺼져도 나중에 다시 그 토론을 열 때 지금까지의 대화가 모두 남아 있어서 이어서 대화할 수 있다. 또한 진행 중인 토론(endedAt이 null)은 입력창이 열려 있어서 계속 말할 수 있고, 끝난 토론(endedAt이 있음)은 입력창이 닫혀 있다.

### 요구사항 원문에서
- `AI 기능 > 완독 후 토론`: "매 턴 메시지 배열 전체를 보내되 캐시된 접두부는 재과금되지 않는다" — 매 턴마다 messagesJson을 업데이트해야 전체 메시지를 보낼 수 있음
- `예외 처리`: "앱 강제 종료 중 토론 → Discussion은 매 턴 저장되므로 재진입 시 이어서 가능" — 매 턴 즉시 저장이 필수 요구사항
- `데이터 모델 > Discussion`: "messagesJson: [{role, content, at}] 배열, ... / startedAt: Instant / endedAt: Instant?" — endedAt은 토론 종료 시에만 기록

### 선행 작업이 남긴 것
- T-703: DiscussionViewModel이 메시지 전송 이벤트를 DiscussionRepository에 보냄
- T-705: 20턴 도달 시 endedAt을 기록하고 입력을 닫는 로직은 여기서 추가

### 관련 파일
| 구분 | 파일 | 이유 | 줄 수 상한 |
| --- | --- | --- | --- |
| 수정 | app/src/main/java/com/logiclinear/reading/data/repo/DiscussionRepository.kt | sendMessage(discussionId, text): Flow<...> 메서드 추가, 매 턴 upsert() 호출 | 200 |
| 참고 | app/src/main/java/com/logiclinear/reading/data/db/DiscussionDao.kt | Upsert 동작: insert or update 동시 지원 | - |
| 수정 | app/src/main/java/com/logiclinear/reading/ui/discussion/DiscussionViewModel.kt | 메시지 전송 후 ViewModel의 messages 상태 업데이트 (즉시 UI 반영) | 200 |
| 참고 | app/src/main/java/com/logiclinear/reading/data/db/Discussion.kt | endedAt nullable: 진행 중이면 null, 종료하면 Instant | - |

### 주의할 점
- DiscussionRepository.sendMessage()는 suspend 함수가 아니라 Flow를 반환해야 아래 단계(T-705의 20턴 마무리)에서 구독 해제 가능.
- 메시지 저장 실패는 아직 처리하지 않음(T-706 "재전송" 기능에서).
- endedAt은 T-705(20턴 마무리)에서 기록됨. 여기서는 null 유지만 확인.

### 완료 조건 체크 방법
- ProcessDeath 시뮬레이션 후 Discussion 재진입: 이전 메시지가 모두 로드되고 입력창이 활성 상태 확인
- Robolectric 또는 androidTest: Discussion.upsert() 호출 후 messagesJson이 변경되었는지 검증
