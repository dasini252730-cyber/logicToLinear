# T-810 토론 화면에서 설정으로 간 뒤 서재 탭을 누르면 토론 화면이 복원됨

## 설명

DiscussionEntry.onOpenSettings가 navigateTopLevel(SETTINGS)를 쓰는데, 서재 위에 쌓인 BookDetail·Discussion이 popUpTo(서재){saveState}로 저장되며 backStackMap[서재 id]에 매달린다(앱 시작 후 탭 전환을 한 번도 안 했을 때). 그 뒤 설정에서 서재 탭을 누르면 navigate(서재){restoreState}가 저장된 스택을 복원해 서재 대신 토론 화면이 뜨고 하단 탭이 사라진다(T-809 적대적 리뷰 경고 5, 바이트코드로 확인). 탭 전환 이력에 따라 동작이 달라진다. 후보: T-809처럼 설정을 토론 위에 쌓고(SettingsRoute(overSearch) 같은 플래그 일반화) 하단 탭을 숨기거나, 설정으로 가기 전에 popBackStack<BookDetailRoute>(inclusive=true, saveState=false)로 비운다.

### 쉽게 말하면
완독 후 토론 화면에서 설정으로 이동했다가 서재 탭을 누르면 설정 화면이 아닌 토론 화면이 다시 뜨는 문제다. T-809와 같은 원인이며, 설정으로 가는 경로를 토론 화면 위에 쌓는 구조로 변경해 탭 전환 시 토론 화면이 걷혀나가지 않도록 해결한다.

### 요구사항 원문에서
- `화면과 사용자 흐름 - 흐름 7 완독 후 토론`: 책 상세에서 토론 목록을 선택해 토론 화면으로 진입. 토론 화면에서 설정으로 이동이 가능해야 함 — 설정 키 입력 후 돌아오는 흐름이 필요
- `예외 처리 - Anthropic 키 미입력 상태에서 분석·토론 시도`: "설정 화면으로 안내" — 토론 중 설정으로의 이동이 정상 경로
- `기술 스택 - AI`: API 키는 설정 화면에서 입력 — 토론 중 키 미입력 상황 발생 가능

### 선행 작업이 남긴 것
- T-809: 동일한 문제를 검색 화면에서 해결하면서 `SettingsRoute(overSearch: Boolean = false)` 플래그 도입. 검색에서는 `navigate(SettingsRoute(overSearch = true))`로 설정을 검색 위에 쌓고, 하단 탭을 숨기며, 뒤로가기로 검색에 돌아옴. 토론에서도 같은 방식 필요.

### 완료 조건 체크 방법
- 완독된 책을 열고 토론 목록에서 토론을 선택 → 토론 화면 표시 → 설정 열기(AiErrorCard의 "설정으로" 또는 직접 구현된 버튼)
- 설정 화면에 상단 뒤로가기가 보이고 하단 탭이 없다 (T-809와 동일)
- 뒤로가기 또는 시스템 뒤로 → 토론 화면 복원 (토론 내용 유지)
- 혹은 설정 화면에서 서재 탭을 누르면 → 서재가 뜬다 (토론이 아님)
- 뒤로가기를 빠르게 두 번 누르면 토론까지 걷혀 책 상세에 머문다 (T-809 수정 사항 참고)

## 작업 메모

- 2026-10-21. T-809와 같은 접근(설정을 하위 화면으로 쌓고 하단 탭 숨김)을 토론에 적용했다. 후보 중 "설정으로 가기 전에 popBackStack으로 비우기"는 토론으로 돌아올 길이 없어져(책 상세 → 토론 목록에서 다시 열어야 함) 버렸다.
- `SettingsRoute(overSearch)` → `SettingsRoute(stacked)`로 개명(T-809 2차 리뷰 경고 7). 검색·토론 모두 `navigate(SettingsRoute(stacked = true))`. `AppNavigation.showBottomBar`는 `isStackedSettings()`면 false.
- 쌓인 설정의 onBack은 `popBackStack<SettingsRoute>(inclusive = true)`: 설정 엔트리 자신까지만 팝하므로 어느 화면 위에 쌓였든 같은 코드이고, 빠르게 두 번 눌러도 둘째 호출은 팝할 설정이 없어 아래 화면이 걷히지 않는다(T-809 2차 경고 5의 일반화).
- "설정으로" 정방향 빠른 두 번 탭(리뷰 경고 1): `navigateStackedSettings()`에 `launchSingleTop = true`. 둘째 호출은 상단 설정 엔트리를 교체해 두 겹이 되지 않는다. 검색 경로도 같은 함수를 쓴다.
- 분석 화면의 "설정 열기"는 그대로 `navigateTopLevel(SETTINGS)`(리뷰 경고 5). 분석은 탭 화면이라 "탭에서 탭으로"가 자연스럽고, 돌아올 때 분석 탭을 다시 누르면 된다. 탭 전환으로 분석 ViewModel 상태(오류 카드)가 사라지는 것은 기존 동작이며 분석 결과는 DB에 저장되므로 수용. 분석은 탭 화면이라 항상 navigateTopLevel로 들어오고, 그때 서재 id가 backStackMap에 먼저 등록되므로 T-809 차단 1의 조건(서재 id 미등록 상태에서 하위 화면을 saveState로 팝)이 성립하지 않는다.
- 완료 조건을 바꿨다. 원래 "토론 → 설정 → 서재 탭 → 서재가 뜬다"였으나 이 접근에서는 쌓인 설정에 탭이 없어 조건이 성립할 수 없다. 새 조건은 "토론 → 설정(탭 없음, 뒤로가기) → 뒤로가기 → 토론. 서재 탭이 토론을 복원하는 경로가 없다".
- 네비게이션 자동 테스트는 의존성이 없어(T-809와 같음) 실기기 확인으로 남긴다(리뷰 경고 2). 새 판단 로직은 `top-level && !stacked` 한 줄이라 순수 함수로 빼서 테스트할 가치가 없다고 판단했다.
- 리뷰 경고 3(토론 위 설정에서 백업 가져오기를 하면 돌아온 토론이 빈 화면): T-810이 새로 만든 경로가 맞다. 크래시는 없고 뒤로가기로 나갈 수 있다. **T-812**로 분리.
- 리뷰 경고 6(주석의 "추천" 탭, Routes.kt 고아 KDoc): T-806 hunk지만 같은 블록이라 함께 고쳤다. 하단 탭은 서재·분석·설정 셋이고 추천은 분석 화면 안의 섹션이다.
- 줄 수: AppNavigation 171/300, Routes 62/300.

## 결과

- 토론 → "설정 열기" → 설정(하단 탭 없음, 상단 뒤로가기) → 뒤로가기(상단·시스템) → 토론(상태 그대로). 설정에서 탭을 누를 수 없으므로 서재 탭이 토론을 복원하는 경로가 사라졌다.
- 변경 파일: `ui/navigation/Routes.kt`, `ui/navigation/AppNavigation.kt`, `ui/settings/SettingsScreen.kt`(주석).
- 확인: `gradlew.bat assembleDebug lintDebug testDebugUnitTest` 통과, 단위 테스트 181개(2026-10-21).
- 실기기 확인(8단계 점검에서): (1) 앱을 새로 시작해 탭을 한 번도 누르지 않은 채 책 상세 → 토론 → AI 오류 카드의 "설정 열기" → 하단 탭이 없고 뒤로가기가 보인다. (2) 뒤로가기 → 토론으로 돌아오고 첫 질문이 자동으로 다시 요청되지 않는다. (3) 뒤로가기를 빠르게 두 번 눌러도 책 상세로 떨어지지 않는다.
