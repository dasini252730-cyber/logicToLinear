## 설명

DiscussionEntry.onOpenSettings가 navigateTopLevel(SETTINGS)를 쓰는데, 서재 위에 쌓인 BookDetail·Discussion이 popUpTo(서재){saveState}로 저장되며 backStackMap[서재 id]에 매달린다(앱 시작 후 탭 전환을 한 번도 안 했을 때). 그 뒤 설정에서 서재 탭을 누르면 navigate(서재){restoreState}가 저장된 스택을 복원해 서재 대신 토론 화면이 뜨고 하단 탭이 사라진다(T-809 적대적 리뷰 경고 5, 바이트코드로 확인). 탭 전환 이력에 따라 동작이 달라진다. 후보: T-809처럼 설정을 토론 위에 쌓고(SettingsRoute(overSearch) 같은 플래그 일반화) 하단 탭을 숨기거나, 설정으로 가기 전에 popBackStack<BookDetailRoute>(inclusive=true, saveState=false)로 비운다.

### 쉽게 말하면
완독 후 토론 화면에서 설정으로 이동했다가 서재 탭을 누르면 설정 화면이 아닌 토론 화면이 다시 뜨는 문제다. T-809와 같은 원인이며, 설정으로 가는 경로를 토론 화면 위에 쌓는 구조로 변경해 탭 전환 시 토론 화면이 걷혀나가지 않도록 해결한다.

### 요구사항 원문에서
- `화면과 사용자 흐름 - 흐름 7 완독 후 토론`: 책 상세에서 토론 목록을 선택해 토론 화면으로 진입. 토론 화면에서 설정으로 이동이 가능해야 함 — 설정 키 입력 후 돌아오는 흐름이 필요
- `예외 처리 - Anthropic 키 미입력 상태에서 분석·토론 시도`: "설정 화면으로 안내" — 토론 중 설정으로의 이동이 정상 경로
- `기술 스택 - AI`: API 키는 설정 화면에서 입력 — 토론 중 키 미입력 상황 발생 가능

### 선행 작업이 남긴 것
- T-809: 동일한 문제를 검색 화면에서 해결하면서 `SettingsRoute(overSearch: Boolean = false)` 플래그 도입. 검색에서는 `navigate(SettingsRoute(overSearch = true))`로 설정을 검색 위에 쌓고, 하단 탭을 숨기며, 뒤로가기로 검색에 돌아옴. 토론에서도 같은 방식 필요.

### 주의할 점
- **명칭 일반화 판단**: T-809 메모에 "overSearch는 '검색에서 왔다'는 의미라 토론·책 상세에도 필요하면 일반화"라고 했으나, 현재 토론이 유일하게 같은 패턴을 쓰는 경로. 일반화할지 유지할지 판단 필요:
  1. overSearch와 유사한 overDiscussion 플래그 추가 (간단하지만 코드 중복)
  2. SettingsRoute(origin: String = "top_level") 같이 출처를 문자열로 변경 (더 확장 가능)
  3. 요구사항과 실제 경로 검증: 책 상세에서도 설정으로 가는지 확인 필요
- AppNavigation.kt의 `navigateTopLevel` 함수(142-148줄)는 `popUpTo(graph.findStartDestination().id)`로 모든 스택을 비우는 구조 → 토론 화면 위에서 호출 시 토론 스택이 저장되어 서재 탭 복원 시 토론이 뜬다
- DiscussionEntry.onOpenSettings는 T-809의 BookSearchEntry.onOpenSettings와 동일한 콜백 체인으로 구조화 필요
- 완료 조건은 "토론 → 설정 → 서재 탭"만 테스트하고, "책 상세 → 설정"이 필요하면 확인 필요

### 완료 조건 체크 방법
- 완독된 책을 열고 토론 목록에서 토론을 선택 → 토론 화면 표시 → 설정 열기(AiErrorCard의 "설정으로" 또는 직접 구현된 버튼)
- 설정 화면에 상단 뒤로가기가 보이고 하단 탭이 없다 (T-809와 동일)
- 뒤로가기 또는 시스템 뒤로 → 토론 화면 복원 (토론 내용 유지)
- 혹은 설정 화면에서 서재 탭을 누르면 → 서재가 뜬다 (토론이 아님)
- 뒤로가기를 빠르게 두 번 누르면 토론까지 걷혀 책 상세에 머문다 (T-809 수정 사항 참고)
