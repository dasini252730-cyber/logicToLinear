### 주의할 점

- Repository는 이 task에서 DB 부분(DAO)만 감싼다. 나중에 T-301(알라딘 API) 등에서 원격 데이터 소스가 추가될 수 있으나, 현 단계에선 불필요.
- ViewModel 생성자 주입을 위해 Factory 패턴이 필요한데, 각 화면의 ViewModel Factory는 T-108 이후에서 구현. 이 task는 AppContainer 구조만 준비.
- android.md: Repository에는 로직이 아니라 데이터 접근만. 선택·합치기·필터링 같은 비즈니스 로직은 domain의 순수 함수로.
- AppContainer는 싱글톤 패턴이거나 Application.appContainer로 접근 가능한 구조. 스레드 안전성은 불필요(1인용 앱).
- 이 단계에선 이미 T-104·T-105에서 만든 DAO들이 있으므로, Repository가 그것들을 감싸기만 하면 됨.

### 완료 조건 체크 방법

- ViewModel이 Repository 생성자 주입: 코드 검토로 `class XxxViewModel(private val repository: XxxRepository)` 형태 확인
- DI 프레임워크 없음: `./gradlew build` 성공하고 의존성에 dagger·hilt 없음 확인 (build.gradle.kts에서 implementation에 없어야 함)
- 런타임 작동: 에뮬레이터/폰에서 앱 실행해 초기화 오류 없는지 확인 (AppContainer 생성 실패하면 앱 크래시)

## 작업 메모

(2026-10-05)

- `AppContainer(context)`: `database`·`bookRepository`·`quoteRepository` 모두 `lazy`. 앱 시작 시 DB를 열지 않아 카메라 2초 원칙(원칙 1)에 영향을 주지 않는다. `ReadingApp : Application`이 하나 들고 있고 매니페스트 `android:name=".ReadingApp"`.
- ViewModel 주입: `CreationExtras.appContainer()` 확장. 각 ViewModel의 `companion object { val Factory = viewModelFactory { initializer { Xxx(appContainer().bookRepository) } } }` 패턴으로 통일(LibraryViewModel·BookFormViewModel·BookDetailViewModel이 사용).
- `BookRepository`: observeByStatus·observeById·getById·observeDefaultReadingBook·add·update·delete·findDuplicateByTitleAndAuthor(공백 정리, 빈 저자→null)·setStatus(별점·소감 유지). 완독 처리는 T-402.
- `QuoteRepository(quoteDao, bookDao)`: observeByBook·observeCount·add(글귀 저장 + 책 lastQuoteAt 갱신, T-206에서 추가)·delete·restore(책이 지워졌으면 false, 리뷰 경고 2·T-404 인계 반영). 테스트 `QuoteRepositoryTest` 3개.
- 리뷰(T-107~T-109 묶음) 경고 5·6: T-107 코드가 T-102 완료 커밋에 먼저 들어갔고 뒤 task 코드가 트리에 섞였다. 커밋 경계가 task와 어긋난 것은 hook이 `done`에서 `git add -A`를 하기 때문으로, 이후 task부터는 done을 task 단위로 바로 찍어 경계를 맞춘다.
- 테스트: `BookRepositoryTest`(상태 변경 시 별점 유지, 중복 찾기 공백 정리, READING 없을 때 null), `AppContainerTest`(파일 DB 생성·저장소 연결). DI 프레임워크 의존성 없음(`app/build.gradle.kts`에 dagger·hilt 없음).
