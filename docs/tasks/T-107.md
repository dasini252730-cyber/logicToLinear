### 쉽게 말하면

이 task는 데이터 계층을 정리한다. 데이터베이스를 직접 쓰는 대신, Repository 클래스가 데이터 접근을 담당하고, Application 클래스에 만드는 DI 컨테이너(AppContainer)에서 이 Repository들을 ViewModel에 주입해 준다. Dagger나 Hilt 같은 라이브러리 없이 수동으로 관리한다.

### 주의할 점

- Repository는 이 task에서 DB 부분(DAO)만 감싼다. 나중에 T-301(알라딘 API) 등에서 원격 데이터 소스가 추가될 수 있으나, 현 단계에선 불필요.
- ViewModel 생성자 주입을 위해 Factory 패턴이 필요한데, 각 화면의 ViewModel Factory는 T-108 이후에서 구현. 이 task는 AppContainer 구조만 준비.
- android.md: Repository에는 로직이 아니라 데이터 접근만. 선택·합치기·필터링 같은 비즈니스 로직은 domain의 순수 함수로.
- AppContainer는 싱글톤 패턴이거나 Application.appContainer로 접근 가능한 구조. 스레드 안전성은 불필요(1인용 앱).
- 이 단계에선 이미 T-104·T-105에서 만든 DAO들이 있으므로, Repository가 그것들을 감싸기만 하면 됨.

### 완료 조건 체크 방법

- ViewModel이 Repository 생성자 주입: 코드 검토로 `class XxxViewModel(private val repository: XxxRepository)` 형태 확인
- DI 프레임워크 없음: `./gradlew build` 성공하고 의존성에 dagger·hilt 없음 확인 (build.gradle.kts에서 implementation에 없어야 함)
- 런타임 작동: 에뮬레이터/폰에서 앱 실행해 초기화 오류 없는지 확인 (AppContainer 생성 실패하면 앱 크래시)
