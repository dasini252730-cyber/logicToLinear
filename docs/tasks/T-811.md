## 설명

BookSearchViewModel의 query·needsKey·keyInvalid는 MutableStateFlow에만 있어, 검색 위 설정 화면에서 키를 복사하러 브라우저로 갔다가 백그라운드에서 프로세스가 죽으면 백스택은 복원되지만 검색어는 빈 문자열이 된다(T-809 2차 리뷰 경고 6). 검색어(와 선택 상태)를 SavedStateHandle에 두어 재시작 뒤에도 남긴다. 결과 목록은 다시 검색하면 되므로 보관하지 않는다.

### 쉽게 말하면
책 검색 화면에 입력한 검색어와 상태(키 오류 여부 등)를 저장해서, 중간에 앱이 강제 종료되어도 검색 화면으로 돌아왔을 때 입력하던 내용이 살아있도록 하는 작업이다. 사용자 입장에서는 설정 화면에서 키를 복사하다가 앱이 종료되어도, 검색 화면에 입력하던 검색어가 그대로 남아 있다.

- `화면과 사용자 흐름`: "화면은 6개다. 앱을 열면 서재가 먼저 뜨고" — 책 검색은 서재의 + 버튼으로 진입하는 선택 경로이다

### 주의할 점
- SavedStateHandle은 Compose의 viewModel() 함수에서 자동으로 전달되므로, Factory에서 이를 받아야 한다. 현재 Factory는 appContainer().bookRepository만 받는 구조이므로 SavedStateHandle 받기 위해 Factory 재구성이 필요하다.
- query·needsKey·keyInvalid 외에 status와 fallbackQuery도 SavedStateHandle 저장 대상인지 확인 필요(완료 조건에는 "검색어"만 명시되어 있음).
- T-809에서 설정 화면 진입 시 navigateTopLevel 또는 백스택 처리로 인한 상태 손실이 있었으므로, SavedStateHandle 도입 후 키 안내 지우기 로직이 정상 동작하는지 테스트 필수.
- 현재 테스트 파일의 vm() 헬퍼 함수는 SavedStateHandle 없이 ViewModel을 직접 생성하므로, SavedStateHandle 복원 테스트를 위해서는 SavedStateHandle을 모킹하거나 Robolectric과 함께 사용할 방안이 필요하다 (현재 testDebugUnitTest에서 Robolectric 사용 중).

## 작업 메모

- 2026-10-21. `BookSearchViewModel(bookRepository, savedState: SavedStateHandle = SavedStateHandle())`. DiscussionViewModel과 같은 패턴(기본값 덕에 기존 테스트는 그대로). Factory는 `createSavedStateHandle()`로 NavBackStackEntry 스코프 handle을 받는다.
- 보관 대상은 검색어(`searchQuery`)와 선택 상태(`searchStatus`, enum name 문자열)뿐. 결과 목록·needsKey·keyInvalid·duplicate·registering은 다시 검색하면 되는 파생 상태라 보관하지 않는다. 특히 (a) `fallbackQuery`를 보관하면 복원 직후 화면의 LaunchedEffect가 직접 입력 폼으로 자동 이동하는 루프가 생기고, (b) `needsKey`를 보관하면 T-809의 `pausedOnce`(remember)가 프로세스 사망으로 초기화돼 안내가 지워지지 않는 상태가 남는다. 깨진 enum 이름은 READING으로 돌아간다.
- 키 이름은 `searchQuery`·`searchStatus`(리뷰 경고 3). NavBackStackEntry handle은 라우트 인자로 초기화되므로 `query`·`status` 같은 일반 이름은 뒤에 라우트 인자가 생기면 조용히 겹친다.
- 저장 길이 상한 `MAX_SAVED_QUERY = 200`(리뷰 경고 2). 붙여넣은 긴 텍스트가 saved instance state 번들(Binder 1MB)에 실리지 않게 저장만 자른다. 화면 값·검색 자체는 자르지 않으므로 사용자 노출 동작은 바뀌지 않는다. 요구사항에 검색어 길이 규정이 없어 사용자 확인 항목에 올린다.
- enum name → 실패 시 READING 복원이 `BackupFile.kt`(runCatching valueOf)와 방식만 다른 중복이다(리뷰 경고 6). 세 번째가 생기면 `BookStatus.fromNameOrDefault()`로 합친다.
- 한 글자 칠 때마다 handle에 쓰는 것은 메모리 맵 갱신이라 비용이 없고, Bundle 직렬화는 onSaveInstanceState 때만 일어난다.
- 줄 수: BookSearchViewModel 124/200, BookSearchViewModelTest 256/400.
