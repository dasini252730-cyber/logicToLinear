## 설명

BookSearchViewModel의 query·needsKey·keyInvalid는 MutableStateFlow에만 있어, 검색 위 설정 화면에서 키를 복사하러 브라우저로 갔다가 백그라운드에서 프로세스가 죽으면 백스택은 복원되지만 검색어는 빈 문자열이 된다(T-809 2차 리뷰 경고 6). 검색어(와 선택 상태)를 SavedStateHandle에 두어 재시작 뒤에도 남긴다. 결과 목록은 다시 검색하면 되므로 보관하지 않는다.

### 쉽게 말하면
책 검색 화면에 입력한 검색어와 상태(키 오류 여부 등)를 저장해서, 중간에 앱이 강제 종료되어도 검색 화면으로 돌아왔을 때 입력하던 내용이 살아있도록 하는 작업이다. 사용자 입장에서는 설정 화면에서 키를 복사하다가 앱이 종료되어도, 검색 화면에 입력하던 검색어가 그대로 남아 있다.

### 요구사항 원문에서
- `화면 흐름 / 흐름 2`: "1. 서재 → + 버튼 → 검색창에 제목 입력. 2. 국립중앙도서관 검색 결과를 제목·저자·발행자로 나열." — 검색어 입력이 흐름의 첫 단계이므로 프로세스 재시작 시에도 보존되어야 한다
- `화면과 사용자 흐름`: "화면은 6개다. 앱을 열면 서재가 먼저 뜨고" — 책 검색은 서재의 + 버튼으로 진입하는 선택 경로이다

### 선행 작업이 남긴 것
- T-809(review): BookSearchScreen의 BookSearchEntry에 LifecycleResumeEffect로 키 오류 안내를 지우는 `clearKeyNotice()` 메서드가 이미 구현됨. SavedStateHandle 추가 시 이 메서드와의 상호작용 확인 필요.

### 주의할 점
- SavedStateHandle은 Compose의 viewModel() 함수에서 자동으로 전달되므로, Factory에서 이를 받아야 한다. 현재 Factory는 appContainer().bookRepository만 받는 구조이므로 SavedStateHandle 받기 위해 Factory 재구성이 필요하다.
- query·needsKey·keyInvalid 외에 status와 fallbackQuery도 SavedStateHandle 저장 대상인지 확인 필요(완료 조건에는 "검색어"만 명시되어 있음).
- T-809에서 설정 화면 진입 시 navigateTopLevel 또는 백스택 처리로 인한 상태 손실이 있었으므로, SavedStateHandle 도입 후 키 안내 지우기 로직이 정상 동작하는지 테스트 필수.
- 현재 테스트 파일의 vm() 헬퍼 함수는 SavedStateHandle 없이 ViewModel을 직접 생성하므로, SavedStateHandle 복원 테스트를 위해서는 SavedStateHandle을 모킹하거나 Robolectric과 함께 사용할 방안이 필요하다 (현재 testDebugUnitTest에서 Robolectric 사용 중).

### 완료 조건 체크 방법
- 검색어 입력 후 설정 화면 → 브라우저 → 개발자 옵션 "액티비티 유지 안함" 켜기 → 앱 강제 종료(Logcat에서 "Process was killed" 확인) → 앱 재시작 → 검색 화면으로 자동 복원(백스택) → 검색어가 남아 있는지 시각적 확인
- `./gradlew testDebugUnitTest` 실행 후 BookSearchViewModelTest에서 SavedStateHandle로 query 상태를 복원하는 테스트가 성공하는지 확인
