## 설명

OpenDocument로 JSON을 읽어 파싱한다. schemaVersion이 앱보다 높으면 거부하고 업데이트 안내, 낮으면 마이그레이션 훅 자리를 둔다. 검증 후 '덮어쓰기 / 합치기' 선택 다이얼로그.

## 작업 브리핑

(2026-10-05, task-briefer 작성)

### 쉽게 말하면
설정 화면의 "가져오기" 버튼을 눌렀을 때 파일 선택 화면(SAF)이 열려서 사용자가 백업 JSON 파일을 고르게 한다. 파일을 읽고 JSON을 파싱한 후, 백업 파일의 schemaVersion을 확인한다. 버전이 앱보다 높으면 "앱을 업데이트하세요" 메시지를 보여주고 가져오기를 중단하고, 버전이 낮으면 마이그레이션 함수를 호출할 자리를 남겨둔다(아직 구현 X). JSON이 손상되었으면 앱이 크래시하지 않고 오류 메시지를 보여준다.

### 요구사항 원문에서
- `백업`: "가져오기: 파일 선택 → 스키마 버전 확인 → '기존 데이터를 지우고 덮어쓸까요, 합칠까요?' 선택. 합치기는 isbn13 또는 제목+저자가 같은 책을 같은 책으로 보고 글귀를 추가한다." — 가져오기 전체 흐름. 이 task는 파일 선택·버전 확인까지만 수행
- `백업`: "JSON 최상위에 schemaVersion 정수를 두고, DB 마이그레이션과 함께 올린다." — schemaVersion 읽기·검증
- `예외 처리`: "가져오기 파일의 schemaVersion이 앱보다 높음 = 가져오기 거부, 앱 업데이트 안내" — 높은 버전 거부 로직
- `예외 처리`: "손상된 JSON은 앱이 죽지 않고 오류를 보여준다" — 파싱 실패 시 예외 처리

### 주의할 점
- **schemaVersion 검증**: 앱의 DB_SCHEMA_VERSION과 백업의 schemaVersion을 비교. 백업 > 앱이면 거부, 백업 < 앱이면 T-505~506에서 처리할 마이그레이션 또는 변환 로직을 호출 (아직 미구현 → 자리표시/예외 처리).
- **JSON 파싱 실패**: kotlinx.serialization 또는 JSON.decodeFromString이 SerializationException을 던질 수 있음. 캐치해서 오류 메시지("파일이 손상되었거나 지원하지 않는 형식입니다")로 보여줌. 앱 크래시 금지.
- **파일 읽기**: ContentResolver를 사용해 SAF로 선택한 URI의 InputStream을 읽음.
- **"앱 업데이트 안내" 메시지**: 요구사항 정확한 문구는 없지만, "이 백업은 더 최신 버전의 앱으로 만들어졌습니다. Play Store에서 앱을 업데이트하세요" 정도.

### 완료 조건 체크 방법
- 설정 화면 "가져오기" 버튼 탭, 파일 선택 다이얼로그 열리는지 확인
- 낮은 schemaVersion을 가진 백업 파일 선택, 파싱 성공 확인 (다음 단계는 덮어쓰기/합치기 선택)
- 높은 schemaVersion(예: 999)을 가진 백업 파일 선택, "앱 업데이트 안내" 메시지 표시 확인
- 손상된 JSON 선택(예: 빈 파일, 문법 오류), "파일 형식 오류" 메시지 표시 확인, 앱이 크래시하지 않는지 확인

## 작업 메모

(2026-10-05)

- "가져오기" → `OpenDocument`(JSON·text·octet-stream 허용: 파일 관리자마다 MIME이 다르다) → `BackupIo.read` → `parseBackup(text)`: 파싱 실패/필수 필드 누락 → `Corrupt`("백업 파일을 읽을 수 없어요"), schemaVersion > 앱 → `TooNew`("이 백업은 더 새로운 앱에서 만들었어요. 앱을 업데이트해 주세요"), 낮으면 `migrateBackup`(지금은 버전만 올림, Room Migration 추가 시 같은 커밋에서 단계 추가) → `Ok`.
- 검증 통과 시 `pendingImport`로 다이얼로그 "기존 데이터를 지우고 덮어쓸까요, 합칠까요?"(요구사항 원문) → 덮어쓰기 / 합치기 / 취소.
- 읽기 자체가 실패(권한·없는 파일)하면 "가져오기에 실패했어요".
