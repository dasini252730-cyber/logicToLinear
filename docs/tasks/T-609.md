## 설명

네트워크·키·서버 오류를 사용자 문구로 보여주고 재시도 버튼을 둔다. 로딩 중 중복 호출을 막는다. 분석 화면에 적용하고 토론 화면도 같은 컴포넌트를 쓰게 만든다.

### 주의할 점
- 오류 메시지 매핑 (요구사항 "예외 처리" 표 및 주석 기반):
  - 401/키 미입력: "API 키를 설정해 주세요" + 설정 화면 버튼
  - 429/한도 초과: "API 호출 한도를 초과했습니다. 내일 다시 시도해 주세요"
  - 5xx/서버 오류: "서버에 일시적 오류가 발생했습니다. 잠시 후 다시 시도해 주세요"
  - 네트워크/타임아웃: "인터넷 연결을 확인해 주세요"
- 로딩 중 중복 호출 방지: ViewModel의 isLoading 플래그 체크. isLoading == true이면 버튼 클릭 이벤트 무시 (또는 버튼 UI 비활성화)
- 재시도 버튼: 클릭 → onRetry() → 동일 호출 재실행. 자동 재시도는 AnthropicClient 수준에서 1회만 (이 컴포넌트는 사용자 수동 재시도)
- 토론 화면도 같은 컴포넌트 사용: DiscussionScreen에서 동일 AiErrorDisplay 컴포저블 재사용
- 토론 특화 처리(T-710에서): 메시지가 로컬에 보관되었고 아직 전송 안 됨 상태일 때 "재전송" 버튼. 이는 T-609의 공통 AiErrorDisplay와는 별개로 토론 UI에서 관리.

### 완료 조건 체크 방법

- `testUnauthorizedErrorShowsSettings`: 잘못된 API 키로 호출 시 "API 키를 설정해 주세요" 메시지와 설정 버튼 보임 확인
- `testRetryButtonRe-executes`: 재시도 버튼 탭 → 동일 호출이 다시 나가고, 성공 시 오류 화면 사라지는지 확인
- `testLoadingButtonDisabled`: 호출이 진행 중일 때 "분석하기" 버튼이 비활성화되고 중복 탭 방지 확인 (실기기 또는 UI 테스트)
- `testRateLimitError`: 429 응답 시 "API 호출 한도를 초과했습니다..." 메시지 확인
- `testServerError`: 500+ 응답 시 "서버에 일시적 오류..." 메시지 확인

## 작업 메모

(2026-10-05)

- `ui/ai/AiErrorCard(failure, onRetry, onOpenSettings, onDismiss, retryEnabled)`: 문구는 `AiResult.Failure.messageRes()`, 버튼은 `action()`(RETRY / OPEN_SETTINGS / NONE). 분석 화면이 쓰고, 토론 화면(T-703)도 같은 컴포저블을 쓴다.
- 재시도 버튼은 `run()`을 다시 부른다(사용자 동작). 자동 재시도 1회는 클라이언트 안에서 끝난 뒤라 여기서는 더 이상 자동으로 부르지 않는다.
- 로딩 중: 실행 버튼 비활성 + 스피너 + "분석하고 있어요", 오류 카드의 재시도도 비활성.
