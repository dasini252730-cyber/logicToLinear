## 설명

결과를 탭하면 7개 필드를 저장해 등록한다. 기본 상태 READING(변경 가능). 같은 isbn13이 있으면 '이미 서재에 있어요'로 막는다.

- [ ] 중복 isbn13 등록 시 차단 메시지가 뜨고 저장되지 않는다

## 작업 브리핑

(2026-10-05, task-briefer 작성)

### 쉽게 말하면

검색 결과 목록에서 책 하나를 탭하면 그 책의 정보(제목, 저자, 출판사, ISBN13, 표지 URL, 카테고리, 소개글)가 DB에 저장되어 서재에 추가된다. 사용자는 기본적으로 상태가 READING으로 설정되어 즉시 글귀 촬영을 시작할 수 있다. 같은 ISBN13을 가진 책이 이미 서재에 있으면 등록을 막고 "이미 서재에 있어요"라는 메시지를 보여준다.

### 요구사항 원문에서

- `책 검색`: "등록 시 title, author, publisher, isbn13, cover, categoryName, description을 저장한다. 같은 isbn13이 이미 있으면 "이미 서재에 있어요"로 막는다." — 이 task는 7개 필드 저장과 isbn13 중복 차단을 구현한다.
- `흐름 2: 책 등록`: "탭하면 등록, 상태는 기본 READING(선택 가능)." — 등록 시 기본 상태를 정의한다.
- `데이터 모델 > Book`: "isbn13 | String? | 알라딘 등록 시에만", "coverUrl | String? | 알라딘 표지 URL. 오프라인 대비 로컬 캐시", "category | String? | 알라딘 categoryName" — 저장할 필드 정의.

### 주의할 점

- 요구사항 원문에서 "이미 서재에 있어요"는 isbn13 중복일 때만 적용된다. 직접 입력 책은 제목+저자로만 경고한다.
- isbn13이 null인 책도 있을 수 있으니 (예: 오래되거나 비표준 책) null 안전성을 확인해야 한다.
- 기본 상태 READING은 요구사항 "책 상태: WANT / READING / DONE"과 "기본 상태 READING(변경 가능)"에서 정의된다.
- 저장 후 화면이 자동으로 이전 화면(서재)으로 돌아가는지, 아니면 다이얼로그나 스낵바로 안내하는지 확인해야 한다.
- 요구사항에서 사용자가 상태를 변경할 수 있다고 했으니, 저장 시 상태 선택 UI가 필요한지 검토한다 (이번 task 범위 내인지, 아니면 별도 task인지).

### 완료 조건 체크 방법

- 검색 결과에서 책을 탭하고 DB에 저장되는지 확인한다.
- Room의 관찰 기능이나 로그로 isbn13, coverUrl, category, description이 저장되었는지 검증한다.
- 같은 isbn13을 가진 책을 다시 등록하려고 하면 "이미 서재에 있어요" 메시지가 나타나고 저장되지 않는지 테스트한다.
- 저장 후 화면이 서재로 돌아가고 새 책이 목록에 추가되는지 확인한다.
