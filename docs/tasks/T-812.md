## 설명

T-810으로 설정이 토론 위에 하위 화면으로 쌓이게 되면서 생긴 경로. 토론 위 설정에서 JSON 가져오기(DB 교체)를 하면 뒤로가기로 돌아온 토론은 discussion == null → loaded = false가 되어 입력창·'첫 질문 받기'·마무리 안내가 모두 없는 빈 화면(제목만)이 남는다. 크래시는 없고 상단 뒤로가기로 나갈 수 있다. 후보: loaded=false이고 로딩이 끝났으면 '토론을 찾을 수 없어요' 안내 + 뒤로가기, 또는 자동으로 책 상세로 팝.

## 작업 브리핑

(2026-10-23, task-briefer 작성)

### 쉽게 말하면
사용자가 토론 화면에서 설정으로 들어가 백업을 가져와 데이터를 교체한 후 뒤로 나가면, 열어둔 토론이 더 이상 없어져서 화면이 텅 빈 상태가 된다. 사용자에게 "이 토론을 찾을 수 없어요" 같은 안내를 보여주고 뒤로 돌려보내거나, 책 상세 화면으로 자동으로 돌려보내는 처리가 필요하다.

### 요구사항 원문에서
- `예외 처리`: "Anthropic 키 미입력 상태에서 분석·토론 시도 | 설정 화면으로 안내. 토론에서는 설정을 하위 화면으로 열고 뒤로가기로 토론에 복귀" — 토론이 이상하게 닫혀도 설정에서 복귀할 수 있어야 한다는 원칙을 적용
- `화면과 사용자 흐름`: "설정 화면의 JSON 내보내기/가져오기" 및 "가져오기: 파일 선택 → 스키마 버전 확인 → 기존 데이터를 지우고 덮어쓸까요, 합칠까요?" — 백업 가져오기가 DB를 교체하면서 토론 ID가 유효하지 않을 수 있다

### 선행 작업이 남긴 것
- T-810: 설정이 토론(또는 검색) 위에 하위 화면으로 쌓이는 구조(SettingsRoute(stacked=true), navigateStackedSettings()). 이로 인해 토론이 백스택에 남아 설정에서 뒤로가기로 돌아올 때 토론 라우트가 복구되지만, 그 사이 DB가 교체되면 discussionRepository.observeById(discussionId)가 null을 반환하게 됨.

### 주의할 점
- 현재 DiscussionScreen은 `!state.loaded` 시 하단 바(입력창, 첫 질문 받기 버튼 등)를 감춘다(line 95). 내용 영역도 비어 있으면 사용자에게는 제목만 보인다.
- 토론이 로딩 중인 상태(초기 진입)와 로딩이 완료되었지만 데이터가 없는 상태(백업 교체)를 구분해야 할 수 있다. 현재는 `loaded = discussion != null`이므로 두 경우 모두 false이다. 시간 경과(예: LaunchedEffect나 stateIn의 WhileSubscribed 타임아웃)를 이용해 구분할 수 있는지 확인 필요.
- 최종 선택(안내 문구 표시 vs 자동 팝)은 요구사항에 명시되지 않았으므로, 작업 중 사용자 지시를 기다리거나 적절한 방식을 선택해야 한다.

### 완료 조건 체크 방법
- 토론 화면 진입 → 상단 "설정으로" 버튼 → 설정 하위 화면 진입 → "가져오기" 버튼 → 백업 파일 선택(기존 데이터를 지우고 덮어쓸까요 선택) → 가져오기 완료 → 뒤로가기 → 토론이 없다는 안내 또는 책 상세 화면이 보인다(empty 또는 auto-pop 중 선택된 방식에 따라)
- 상단 뒤로가기 또는 시스템 뒤로 버튼으로 원래 흐름(책 상세)으로 돌아갈 수 있는지 확인
