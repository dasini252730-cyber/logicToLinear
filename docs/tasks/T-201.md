## 설명

CameraX를 추가하고 카메라 권한 요청 흐름을 만든다. 프리뷰가 뜨는 카메라 화면을 홈 라우트에 연결한다. 권한 거부 시 안내 문구와 설정 열기 버튼.

- [ ] 권한 거부 시 앱이 죽지 않고 안내가 보인다

## 작업 브리핑

(2026-10-05, task-briefer 작성)

### 쉽게 말하면

앱을 열면 2초 안에 카메라가 떠야 한다는 제품 원칙을 실현하기 위해 CameraX 라이브러리를 의존성에 추가하고, 사용자 권한 요청·거부 흐름을 완성한다. 권한을 허용하면 카메라 미리보기가 화면에 뜨고, 거부하면 앱이 멈추지 않고 설정 앱을 열 수 있도록 안내한다.

### 요구사항 원문에서

- `기술 스택 > 카메라`: "CameraX | 촬영 후 비트맵을 OCR에 넘기고 사진은 폐기" — T-201에서 CameraX 기초 마련
- `화면과 사용자 흐름 > 카메라(홈)`: "앱 시작 시 | 글귀 촬영. 상단에 현재 선택된 책 이름" — 홈 라우트가 카메라 화면이어야 함
- `설계 원칙`: "앱을 열면 2초 안에 카메라가 떠야 한다. 글귀 저장이 가장 자주 쓰는 동작이다." — T-201의 최우선 목표
- `설계 원칙`: "사용자는 한 명이다. 로그인, 서버, 계정은 만들지 않는다." — 권한 거부 후 설정 열기만 제공, 계정 가입 등 없음

### 주의할 점

- **T-108 선행 필수**: T-201을 시작할 때 T-108이 완료되어 HomeRoute가 이미 있어야 한다. 없으면 라우트 연결이 실패한다.
- **권한 모델**: Android 6.0(API 26)부터 런타임 권한 요청이 필수다. 허용/거부 모두 처리해야 앱이 멈추지 않는다.
- **CameraX 라이프사이클**: Preview 바인딩을 Activity/Fragment 라이프사이클에 묶어야 한다. HomeScreen의 SideEffect나 ViewModel에서 라이프사이클 Event를 구독해야 할 수 있다.
- **2초 목표**: OCR이 없는 이 단계에서는 권한 요청 후 프리뷰 표시만 측정한다. OCR 시간은 T-203에서 추가된다.

### 완료 조건 체크 방법

- 앱 실행 → "CAMERA 권한 허용하시겠습니까?" 대화상자 → 허용 → 카메라 미리보기 화면이 화면 전체에 표시됨 확인
- 앱 재실행 → 권한 거부 → 안내 문구(예: "카메라 권한이 필요합니다") + "설정 열기" 버튼 표시 → 버튼 탭 → 기기 설정 앱의 권한 화면 열림 확인
- 기기 저장소·갤러리에 임시 파일이 생기지 않음 확인 (아직 촬영 후 저장 기능은 없으므로 자동)
