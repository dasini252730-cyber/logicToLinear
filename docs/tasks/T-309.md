## 설명

사용자 결정(2026-10-05): 카카오 대신 국립중앙도서관 소장자료 검색 Open API(GET https://www.nl.go.kr/NL/search/openApi/search.do?key=&kwd=&srchTarget=title&apiType=json&pageNum=1&pageSize=10&category=도서)를 쓴다. 인증키는 관리자 승인(업무일 1~2일) 대기 중. 조사 결과: 오류는 HTTP 200에 {errorCode,errorMsg}로 온다(010 키 없음, 011 유효하지 않은 키, 000·101 서버 오류, 012~015 파라미터 오류). Content-Type은 text/json;charset=UTF-8이라 Retrofit 컨버터 미디어 타입을 맞춰야 한다. 응답 필드는 공식 표상 total·result[]·title_info·author_info·pub_info·pub_year_info·isbn·call_no·type_name·detail_link·kdc_code_1s·kdc_name_1s(실제 JSON 키 표기는 키 승인 후 실호출로 확인). 표지·소개글은 없고 KDC 대분류로 Book.category를 채울 수 있다. KakaoBookApi/KakaoBookClient를 NlBookApi/NlBookClient로 바꾸고 SecretKey.KAKAO_REST→NL_OPENAPI, 설정 문구·추천 링크(detail_link)를 바꾼다.

## 작업 메모

(2026-10-05~06)

- 사용자 지시 "폰이 필요한 것 외에 전부 진행"으로 인증키 승인 전에 구현했다(`--force` 시작, T-001 승인 대기). task-briefer 브리핑은 건너뛰었다(T-308 메모·조사 결과가 브리핑 역할). 승인 뒤 실호출로 JSON 키 표기를 확인하는 완료 조건 1만 남는다.
- `data/remote/books/NlBookApi.kt`: `GET NL/search/openApi/search.do?key&kwd&srchTarget=title&apiType=json&pageNum=1&pageSize=10&category=도서`. 응답 `{result:[…]}` 또는 `{errorCode, errorMsg}`. 필드 표기가 공식 표(snake_case)와 오류 응답(camelCase)이 달라 `@SerialName("title_info") @JsonNames("titleInfo")`로 둘 다 받는다. `total`은 문자열/숫자가 섞일 수 있어 읽지 않는다.
- 후처리: 검색어 강조 `<span>` 태그 제거, 저자 "지음·저·옮김" 꼬리 제거와 `;`→`, `, ISBN 문자열에서 13자리 하나 추출(세트 표기 대응), `detail_link` 상대 경로를 절대 URL로. 같은 isbn13(없으면 제목+저자)은 한 건으로 합친다. `category`는 `kdc_name_1s`(KDC 대분류)로 채운다. 표지·소개글은 빈 값(사용자 결정).
- `NlBookClient`: 키는 쿼리 파라미터라 로깅 인터셉터 금지 유지. errorCode 010·011 → InvalidKey(설정 안내), 000·101 → Network(직접 입력 폼), 012~015 → ApiError. HTTP 401/403 → InvalidKey, 5xx·IO·직렬화 실패(HTML·XML 본문) → Network. `BookSearchResult.ApiError.code`는 T-308에서 미리 `String?`으로 바꿔 둔 것을 그대로 쓴다.
- 호출부: `SecretKey.KAKAO_REST`→`NL_OPENAPI`(prefName `nl_openapi_key`, 이전 카카오 값은 암호화 저장소에 남지만 쓰이지 않음), 설정 화면 칸·문구 "국립중앙도서관 인증키", 검색 화면 키 안내 문구, AppContainer `NlBookClient.create`. 카카오 소스 3개 삭제. app 안 `kakao|카카오` grep 0건.
- 문서: `docs/요구사항.md`의 알라딘 18곳과 `rules/product-principles.md` 2곳을 국립중앙도서관으로 고쳤다(사용자 2026-10-05 결정 근거). 표지·소개글 포기, KDC 대분류로 분류 복구를 명시.
- T-308에서 이월한 항목: (1) isbn13 없는 결과의 중복 검사 — NL은 isbn을 대부분 주고, 클라이언트가 isbn13 없으면 제목+저자로 합치므로 Repository 변경은 하지 않았다. (2) 분석 프롬프트 "장르·카테고리 통계" 줄 — category가 KDC로 다시 채워지므로 그대로 둔다. (3) SettingsViewModel 분리 — 이번 변경은 이름 치환뿐이라 줄 수 변동 없음(180/200), 분리는 다음에 설정을 건드릴 때.
- 리뷰 반영(2026-10-06): 저자 꼬리 정규식을 `\s+` 경계로(차단: "구글"→"구" 절단), 한자형(著·編·譯·共著) 추가. `extractIsbn13`은 978/979로 시작하는 13자리만. `errorCode`가 숫자로 와도 `padStart(3,'0')`로 정규화. 공식 표에 없는 `image_url` 추측 필드와 안 쓰는 `type_name`·`pub_year_info` 제거. 판본 합치기 키에 발행자 추가(isbn 없을 때 제목·저자·발행자 모두 같을 때만). **응답 형식 가드**: `result` 키가 없거나 `total`>0인데 `result`가 비면 `ApiError("shape")`로 보내 "검색 결과 없음"으로 오진하지 않게 하고 logcat `NlBookClient: unexpected response shape`를 남긴다 — T-307 실기기 검색 때 이 로그가 보이면 키 표기를 고친다. 요구사항 "예외 처리" 표에 검색 키 미입력/무효 두 행을 추가(기존 문구 그대로). 기기에 남는 옛 `kakao_rest_key` 값은 코드로 접근 불가, 앱 데이터 삭제로만 지워진다(1인 앱·출시 전이라 수용).
- 실호출 확인(키 승인 뒤): `curl "https://www.nl.go.kr/NL/search/openApi/search.do?key=…&kwd=토지&srchTarget=title&apiType=json&pageSize=2&category=도서"`로 키 표기·`detail_link` 형태·`isbn` 형태·`kdc_name_1s` 값을 보고 `NlItem`과 테스트 샘플을 맞춘다.
