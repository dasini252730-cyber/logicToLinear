### 주의할 점
- **실기기 없음**: 현재 작업 환경에는 연결된 실기기가 없다(adb devices 출력 없음). 따라서 실제 측정은 불가능하며, 측정값을 기록할 수 없다
- **측정 방법 (실기기 있을 때)**:
  1. 장치에 앱을 설치: `adb install app/build/outputs/apk/debug/app-debug.apk`
  2. 콜드 스타트 측정: `adb shell am start -W -n com.logiclinear.reading/.MainActivity` (출력에서 "ThisTime" 값 기록)
  3. 또는 logcat 확인: `adb logcat | grep "Displayed"`로 시스템이 기록한 시간 확인
  4. 5분 이상 대기 후 3회 반복 측정
- **최적화 후보**:
  - AppContainer의 lazy 초기화: Repository·OcrRecognizer 등 시작 시 불필요한 것 lazy로 변경
  - 스플래시 화면 제거 또는 단축
  - CameraX 프리뷰 바인딩을 HomeViewModel.bindCamera()에서 HomeEntry의 LaunchedEffect 시점으로 앞당기기
  - Room 데이터베이스 초기화를 백그라운드 스레드로 미루기
- **이 task에서 하면 안 되는 것**:
  - T-212 이상의 기능 추가
  - 기능 동작 변경(성능만 개선)
  - 코드 품질이 떨어지는 트릭(무의미한 병렬화, 결과 캐싱 등)

## 작업 메모

(2026-10-05) 실기기가 없어 측정은 못 했다. 코드 수준에서 할 수 있는 것만 했다.

- 시작 경로: `ReadingApp.onCreate`는 `AppContainer` 객체만 만든다(모두 lazy, 작업 없음). `MainActivity`는 `enableEdgeToEdge` + `AppNavigation` 컴포지션. `HomeEntry`가 권한을 확인하고 `LaunchedEffect`에서 `ProcessCameraProvider.awaitInstance` → 바인딩. 스플래시 없음.
- 홈 첫 프레임에서 DB가 열린다: `HomeViewModel.uiState`가 `observeDefaultReadingBook()`을 구독하므로 Room이 열리고 `book` 테이블을 한 번 읽는다. 작은 DB라 수십 ms 수준으로 예상하지만 측정 전까지는 추정이다. 2초를 넘기면 첫 후보는 이 구독을 카메라 바인딩 뒤로 미루는 것이다.
- ML Kit 인식기는 lazy라 첫 셔터 때 초기화된다. 콜드 스타트에는 영향이 없지만 첫 촬영 지연으로 보일 수 있다. 측정 후 필요하면 프리뷰가 뜬 뒤 백그라운드에서 미리 만들 수 있다.
- 측정 방법(T-005 뒤): `adb shell am start -W -n com.logiclinear.reading/.MainActivity`의 `TotalTime`, 또는 `adb logcat | grep Displayed`. 콜드 스타트는 `adb shell am force-stop` 뒤 측정. 3회 중앙값, debug 빌드와 release 빌드를 구분해 기록.
