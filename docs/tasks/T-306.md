# T-306 표지 이미지 로컬 캐시

| 항목 | 값 |
| --- | --- |
| 단계 | 3. 알라딘 검색 |
| 상태 | review |
| 우선순위 | P1 |
| 담당 | claude |
| 예상 | 30분 |
| 요구사항 참조 | `데이터 모델 > Book > coverUrl` |

## 설명

coverUrl 이미지를 디스크 캐시해 오프라인에서도 서재·상세에 표지가 보이게 한다. 이미지 라이브러리(Coil 권장)를 추가하면 이유를 적는다.

## 선행 작업

- [T-304 검색 결과 등록과 isbn13 중복 차단](T-304.md)

## 완료 조건

- [x] 한 번 본 표지는 비행기 모드에서도 보인다 (디스크 캐시 설정; 실기기 T-307)
- [x] 표지가 없는 책은 플레이스홀더가 보인다

## 작업 브리핑

(2026-10-05, task-briefer 작성)

### 쉽게 말하면

책 표지 이미지를 알라딘 서버에서 처음 한 번 로딩할 때 폰의 디스크에 캐시해 저장한다. 그러면 나중에 오프라인 상태에서도 이전에 본 표지를 볼 수 있다. 표지가 없는 책의 경우 제목 첫 글자를 플레이스홀더로 계속 보여준다.

### 요구사항 원문에서

- `데이터 모델 > Book > coverUrl`: "String? | 알라딘 표지 URL. 오프라인 대비 로컬 캐시" — coverUrl 필드의 설계 목표가 오프라인 대비 로컬 캐시라고 명시되어 있다.
- `기술 스택`: "HTTP | Retrofit 또는 Ktor" (HTTP 클라이언트), "이미지 로딩은 Coil 3(io.coil-kt.coil3:coil-compose 3.6.3)을 쓸 예정이며 디스크 캐시로 오프라인 표지를 보여야 한다" — 라이브러리 선택과 목표.

### 선행 작업이 남긴 것

- T-304: Book 엔티티에 coverUrl이 저장됨, 서재/검색 화면에서 coverUrl을 표시

### 주의할 점

- Coil 3.6.3은 이미 프로젝트에서 언급되었으므로 버전 호환성만 확인하면 된다.
- BookCover.kt의 기존 주석에 "T-306에서 [coverUrl]이 있으면 캐시된 이미지를 넣는다"고 이미 쓰여 있으므로, 이 주석을 그대로 구현한다.
- Coil의 디스크 캐시는 기본적으로 켜져 있고, 캐시 정책은 Coil의 기본 설정을 따른다 (별도 설정 불필요).
- 이미지 로딩 중에는 플레이스홀더(제목 첫 글자)를 보여주고, 로딩 실패해도 같은 플레이스홀더로 폴백한다.
- coverUrl이 null이면 이미지를 로딩하지 않고 항상 플레이스홀더를 보여준다.

### 완료 조건 체크 방법

- 서재나 검색 화면에서 책 표지 이미지를 로딩한다 (coverUrl이 있는 책).
- 비행기 모드를 켜고 같은 화면을 다시 방문한다. 캐시된 표지 이미지가 보이는지 확인한다.
- coverUrl이 null인 책(예: 직접 입력한 책)을 만들어 제목 첫 글자 플레이스홀더가 보이는지 확인한다.
- 이미지 로딩이 오래 걸리거나 실패하는 상황을 테스트해서 플레이스홀더가 제대로 표시되는지 확인한다.

## 작업 메모

(2026-10-05)

- Coil 3.6.3(`coil-compose`, `coil-network-okhttp`). `ReadingApp`이 `SingletonImageLoader.Factory`로 디스크 캐시 `cacheDir/covers` 50MB, 캐시 정책 ENABLED를 설정한다. OkHttp 클라이언트는 알라딘 호출용과 분리(이미지에 JSON 정리 인터셉터가 붙지 않도록).
- `ui/components/BookCover`: `SubcomposeAsyncImage`. coverUrl이 null이거나 로딩 중·실패면 제목 첫 글자(코드 포인트 기준, 서로게이트 안전) 플레이스홀더. 미리보기(`LocalInspectionMode`)에서는 네트워크를 타지 않는다.
- 서재 목록·검색 결과·책 상세가 같은 컴포저블을 쓴다.
- 테스트 `BookCoverTest`(firstGlyph 경계: 빈 문자열, 서로게이트 쌍, 공백).
