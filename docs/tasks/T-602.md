## 설명

DONE 책 전체(제목·저자·카테고리·별점·한 줄·완독일), 글귀 전체(책 제목+텍스트+페이지), 최근 토론별 마지막 사용자 발언 3개를 모아 프롬프트용 텍스트로 만든다. 증분·샘플링 없이 전체를 보낸다.

## 작업 브리핑

(2026-10-05, task-briefer 작성)

### 쉽게 말하면
분석 버튼을 누르면 Claude에게 "당신이 읽은 책과 글귀를 토대로 당신의 독서 취향을 분석해 달라"고 요청한다. 이 작업은 그 요청에 들어갈 데이터(책 목록, 글귀, 최근 토론)를 DB에서 모아서 텍스트로 만드는 부분이다.

### 요구사항 원문에서
- `AI 기능 > 취향 분석·추천` 입력 섹션: "DONE 책 전체: 제목, 저자, 카테고리, 별점, 한 줄, 완독일 / 글귀 전체: 책 제목 + 글귀 텍스트 + 페이지 / 최근 토론이 있으면 각 토론의 마지막 사용자 발언 3개" — 정확히 무엇을 모을지 명시
- `확정된 결정 > 토큰 절약`: "증분 전송·샘플링은 하지 않음(사용자 결정)" — 매번 전체 데이터를 모아 보낸다
- `AI 기능`: "입력(1회 호출): DONE 책 전체..., 글귀 전체..., 최근 토론..." — 한 번의 API 호출에 필요한 전체 입력

### 선행 작업이 남긴 것
- T-105: Discussion·Analysis 엔티티와 DAO 구현. Discussion은 messagesJson 배열을 가짐
- T-403: BookDetailScreen에서 책 상세와 글귀 목록 표시. BookDao·QuoteDao 쿼리 완성

### 주의할 점
- 마지막 사용자 발언 3개: Discussion의 messagesJson을 역직렬화해 role=="user"인 메시지만 역순으로 3개까지 추출. 토론이 3턴 미만이면 있는 만큼만.
- 책의 카테고리, 설명(description)이 null이면 빈 문자열로 처리. (알라딘 검색 실패한 직접 입력 책)
- 반환값은 AnalysisInput이라는 data class로, 반드시 inputBookCount와 inputQuoteCount 필드를 포함해야 한다(완료 조건).
- 증분·샘플링 금지: 매 호출마다 DB의 모든 DONE 책, 모든 글귀, 모든 토론의 마지막 메시지를 포함

### 완료 조건 체크 방법
- `testBuildAnalysisInput`: BuildAnalysisInputTest에서 DONE 책 5권, 글귀 10개, 토론 2개로 테스트해 반환값의 inputBookCount==5, inputQuoteCount==10 확인 (`./gradlew testDebugUnitTest`)
- `testInputCounts`: 책 수·글귀 수가 정확히 세어지고 반환값에 포함되는지 확인
