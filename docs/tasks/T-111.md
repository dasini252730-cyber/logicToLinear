## 작업 브리핑

(2026-10-05, task-briefer 작성)

### 쉽게 말하면

서재에서 책을 탭했을 때 보이는 책의 상세 정보 화면을 만든다. 표지, 제목, 저자, 출판사, 카테고리, 현재 상태를 표시하고, 책의 상태에 따라 상태 변경 버튼("읽기 시작" 또는 "다시 읽기")을 보여준다. 완독 처리 버튼은 아직 구현하지 않지만 자리를 미리 배치해 둔다.

### 요구사항 원문에서

- 화면과 사용자 흐름 > 책 상세 "표지, 정보, 글귀 목록, 별점·한 줄, 토론 목록, 완독 처리 버튼" — 이 task는 표지와 정보(제목, 저자, 출판사, 카테고리, 상태)만 구현, 글귀·별점·토론·완독 처리는 이후 단계
- 책 상태 전이 "WANT → READING: 책 상세에서 \"읽기 시작\" 버튼 / DONE → READING: \"다시 읽기\" 버튼. 기존 별점·소감은 유지하고 완독 시 덮어쓴다" — 상태별 버튼 노출과 DONE→READING 시 데이터 유지 규칙
- 제품 원칙 "사용자 노출 문구는 요구사항 원문 그대로 써야 한다" — 버튼 텍스트는 정확히 일치

### 주의할 점

- 상태별 버튼: WANT 상태일 때만 "읽기 시작" 표시, DONE 상태일 때만 "다시 읽기" 표시, READING 상태일 때는 버튼 미표시
- DONE→READING 전이 시 rating, oneLiner, finishedAt은 유지. 이는 나중에 완독을 다시 처리할 때 이전 기록을 덮어쓸 수 있게 하기 위함
- 표지 표시: coverUrl이 있으면 URL 이미지 표시, 없으면 제목 첫 글자를 배경 색상 위에 표시 (T-109의 플레이스홀더 패턴 참고)
- 완독 처리 버튼은 아직 구현하지 않으므로, UI에 placeholder 버튼이나 숨겨진 자리를 미리 배치하면 나중에 쉽게 연결 가능
- T-111이 T-112(삭제)의 선행 작업이므로, 메뉴나 시스템 백버튼 처리는 단순히 뒤로 가기만 구현 (삭제 메뉴는 T-112에서 추가)

### 완료 조건 체크 방법

- 상태에 따라 알맞은 버튼만 표시: WANT 상태 책을 열어 "읽기 시작" 버튼 확인, DONE 상태 책을 열어 "다시 읽기" 버튼 확인, READING 상태 책을 열어 상태 전이 버튼 없음 확인
- 다시 읽기 시 데이터 유지: DONE 상태 책 상세에서 "다시 읽기" 클릭 후 서재에서 READING 탭으로 이동해 그 책이 보임을 확인, 동일 책을 다시 완독 처리할 때 기존 rating·oneLiner를 덮어쓸 수 있는지 확인 (정확히는 T-113 완독 처리 화면에서 확인)
