### 쉽게 말하면
사용자가 완독한 책과 이야기를 나눌 때, Claude에게 줄 지시문(프롬프트)을 만든다. 지시문은 두 부분으로 나뉜다: (1) Claude에게 "책 친구 역할을 해 줄래?" 하는 역할 설정, (2) 그 책의 제목·저자·소개글·별점·한 줄 소감·글귀를 모두 담은 책 정보. 이 중 책 정보 부분은 프롬프트 캐싱 기술로 표시해 API 비용을 절감한다.

### 요구사항 원문에서
- `AI 기능 > 완독 후 토론`: "시스템 프롬프트에 그 책의 제목·저자·소개글·별점·한 줄·글귀 전체를 넣고, 이 부분을 `cache_control: {type: ephemeral}`로 캐싱한다. 매 턴 메시지 배열 전체를 보내되 캐시된 접두부는 재과금되지 않는다." — 캐싱 전략과 시스템 블록 구성
- `AI 기능 > 완독 후 토론`: "역할: '책 친구'. 먼저 질문 하나를 던지고, 사용자 답에 이어 꼬리 질문을 한다. 한 번에 질문 1개, 답변은 3~4문장 이내. 반박보다 '왜 그렇게 느꼈는지'를 끌어내는 쪽." — 역할 프롬프트 작성 기준
- `AI 기능 > 완독 후 토론`: "max_tokens는 토론 400, 분석 2000" — 토론 max_tokens 값

### 주의할 점
- 요구사항에서는 "책 컨텍스트에만 cache_control이 붙는다"고 명시. 역할 프롬프트 블록은 cache_control을 붙이지 않는다.
- 시스템 블록은 정확히 2개여야 한다(역할 1개, 책 컨텍스트 1개).
- 리소스 파일 읽기는 호출 시점에 일어나야 테스트에서 mocking 가능하다(T-602, T-603 패턴 참고).
