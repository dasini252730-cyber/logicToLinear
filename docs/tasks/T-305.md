### 쉽게 말하면

알라딘 검색이 실패하는 여러 상황(결과가 없음, 네트워크 오류, API 호출 한도 초과)을 모두 같은 방식으로 처리한다. 검색 화면에서 직접 입력 폼으로 전환하면서, 사용자가 입력한 검색어를 제목 필드에 미리 채워준다. 이렇게 하면 사용자가 검색 실패에 좌절하지 않고 쉽게 책 정보를 직접 입력할 수 있다.

### 요구사항 원문에서

- `예외 처리`: "알라딘 검색 결과 없음 | 직접 입력 폼으로 전환", "알라딘 호출 한도 초과·오프라인 | 직접 입력 폼으로 전환, 표지·장르는 비움" — 세 가지 오류 상황의 처리 방식을 정의한다.
- `흐름 2: 책 등록`: "결과 없음 또는 오프라인 → "직접 입력" 버튼 → 제목·저자만 받아 등록." — 예외 경로에서 직접 입력 폼으로의 전환을 정의한다.

### 주의할 점

- 요구사항 "예외 처리" 표에서 세 가지 상황을 구분한다: (1) 결과 없음, (2) 오프라인·한도 초과. 모두 직접 입력 폼으로 이동하되, (2)에서는 "표지·장르는 비움"이라고 했다. 하지만 직접 입력 폼은 기본적으로 표지와 장르 필드를 채우지 않으므로, 이 구분은 검색 결과 저장 시(T-304)에 이미 처리되어 있을 수 있다.
- BookFormRoute(initialTitle="검색어")를 사용해서 검색어가 제목 필드에 표시되도록 한다. BookFormScreen이 이 파라미터를 받는지 확인해야 한다.
- 로딩 중 오류가 발생하면 로딩 스피너를 없애고 직접 입력 화면으로 전환해야 한다.
- 사용자가 검색 중에 뒤로가기를 누르거나 화면을 벗어나면 요청을 취소해야 한다.

### 완료 조건 체크 방법

- 비행기 모드를 켜고 검색을 시도한다. 로딩이 시작되다가 실패하고 직접 입력 폼으로 전환되는지 확인한다.
- 직접 입력 폼의 제목 필드에 검색어(예: "해리 포터")가 들어가 있는지 확인한다.
- 결과가 없는 검색어(예: "zzzzzzzzzzz")를 입력해서 같은 방식으로 직접 입력 폼으로 전환되는지 테스트한다.
- 알라딘 API 한도를 초과했을 때의 응답을 모의하거나, 실제로 한도에 도달했을 때 처리되는지 확인한다.
