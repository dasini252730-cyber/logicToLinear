## 설명

ImageCapture로 촬영해 메모리 상 Bitmap만 얻는다. 파일로 저장하지 않고, OCR이 끝나면 recycle한다. 회전(EXIF) 보정을 포함한다.

### 쉽게 말하면

카메라 셔터 버튼을 누르면 CameraX의 ImageCapture로 사진을 촬영하되, 메모리에만 Bitmap을 만들고 기기 파일 시스템에는 저장하지 않는다. EXIF 회전 값을 읽어 세로·가로 촬영을 올바른 방향으로 보정한 후, 다음 단계(OCR)로 Bitmap을 넘기고 사용이 끝나면 즉시 메모리에서 폐기한다. 이 방식으로 "사진 원본은 저장하지 않는다"는 제품 원칙을 구현한다.

### 요구사항 원문에서

- `확정된 결정 > 사진 원본`: "저장하지 않음, 추출된 텍스트만 저장" — T-202의 핵심 요구사항
- `흐름 1: 글귀 저장` 단계 2: "셔터 → ML Kit OCR 실행 (로딩 1초 내외)." 그리고 단계 5: "사진은 메모리에서 폐기" — 사진 폐기 시점과 프로세스
- `기술 스택 > 카메라`: "촬영 후 비트맵을 OCR에 넘기고 사진은 폐기" — T-202의 정확한 책임
- `예외 처리 > 예외 상황`: 사진 자체는 저장되지 않으므로 관련 예외는 없음

### 주의할 점

- **파일 저장 금지**: File.createTempFile(), FileProvider, MediaStore 등을 쓰지 않는다. 메모리상 Bitmap만 생성한다.
- **EXIF 회전**: ImageCapture로 얻은 Bitmap은 EXIF 태그가 없을 수 있다. CameraX가 센서 방향(sensorOrientation)을 이미 반영할 수도 있고, 앱이 명시적으로 보정해야 할 수도 있다. 테스트로 세로·가로 촬영을 직접 확인해야 한다 (기기 미연결이면 T-202 완료 후 사용자가 확인).
- **Bitmap recycle**: OCR이 끝난 직후 `bitmap.recycle()`을 호출해 메모리를 즉시 해제한다. 메모리 누수 방지.
- **T-201과의 협력**: T-201의 Preview는 프리뷰 표시용, T-202의 ImageCapture는 촬영용. 둘이 동일한 CameraX Session 안에 바인딩되어야 한다.

### 완료 조건 체크 방법

- 앱에서 셔터 버튼 탭 → 갤러리·파일 매니저에서 새 사진 파일이 생기지 않음 확인 (재부팅 후 갤러리 새로고침으로도 파일이 나타나지 않아야 함)
- 기기를 세로로 들고 촬영 → Bitmap의 가로·세로 픽셀 비율이 세로 비율(높이 > 너비)인지 확인
- 기기를 가로로 돌려 촬영 → Bitmap의 가로·세로 픽셀 비율이 가로 비율(너비 > 높이)인지 확인
- Android Studio Profiler의 Memory 탭에서 촬영 후 OCR 종료 직전까지 Bitmap 메모리 상승을 확인, recycle 후 하락하는지 확인 (확인 필요 - 기기 연결 후)
