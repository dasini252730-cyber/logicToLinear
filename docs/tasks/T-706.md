## 작업 브리핑

(2026-10-05, task-briefer 작성)

### 쉽게 말하면
사용자가 메시지를 입력하고 전송 버튼을 누렀는데 네트워크 연결이 끊어져 있거나 서버가 응답하지 않으면, 그 메시지는 "전송 안 됨" 상태로 표시되고 사라지지 않는다. 사용자는 나중에 "다시 보내기" 버튼을 눌러 같은 메시지를 다시 전송할 수 있고, 성공하면 메시지가 정상 상태로 바뀐다.

### 요구사항 원문에서
- `예외 처리`: "토론 중 네트워크 끊김 → 사용자 메시지는 로컬에 보관, 재전송 버튼" — 로컬 보관과 재전송 UI
- `AI 기능 > 비용 통제`: "네트워크 오류·키 오류는 사용자에게 보여주고 재시도 버튼을 둔다. 자동 재시도는 1회만" — 자동 재시도는 AnthropicClient에서 이미 구현, 여기서는 수동 재시도 버튼

### 선행 작업이 남긴 것
- T-705: 메시지 전송 로직이 완성되고, 성공/실패를 구분

### 주의할 점
- 메시지 상태: 화면에서는 ChatMessage가 아니라 DraftMessage로 관리. 데이터베이스에는 여전히 ChatMessage만 저장(PENDING 메시지는 DB 미저장, 재전송 성공 후에 저장).
- 재전송 성공 후: messagesJson에 정상 메시지로 저장되고, 화면에서도 SENT 상태로 바뀜.
- 비행기 모드: 시뮬레이션을 위해 OkHttp 오류(IOException)를 발생시키거나, 테스트에서 가짜 AnthropicClient를 사용해 Network 실패 반환.

### 완료 조건 체크 방법
- 비행기 모드 또는 네트워크 차단: 메시지 전송 시 "전송 안 됨" 표시 및 재전송 버튼 노출 확인
- 비행기 모드 해제 후 재전송: 메시지가 정상 상태로 바뀌고 AI 응답이 이어짐 확인
- 데이터베이스: 재전송 성공 후 Discussion.messagesJson에 사용자 메시지가 저장됨 확인

## 작업 메모

(2026-10-05)

- `DiscussionMessage.failed` 필드(옛 저장 형식과 호환: 없으면 false). 호출 실패 시 마지막 AI 메시지 뒤의 사용자 메시지들을 failed로 저장한다. 화면은 "전송 안 됨" + "재전송" 버튼, 실패 메시지가 있는 동안 새 전송은 막는다(순서 보존).
- `resend`는 failed를 풀고 저장한 뒤 같은 경로로 호출한다. API 요청에서는 failed 메시지를 제외하고, 같은 role이 연속되면 합친다.
