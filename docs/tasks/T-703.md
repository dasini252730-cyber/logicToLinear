## 작업 브리핑

(2026-10-05, task-briefer 작성)

### 쉽게 말하면
사용자가 토론 화면에서 보는 대화창을 만든다. 위쪽에는 Claude와 사용자가 나눈 메시지들이 시간 순서대로 나열되는데, Claude의 메시지는 한쪽 색으로, 사용자 메시지는 다른 색으로 구분해서 본다. 아래쪽에는 텍스트를 입력하고 전송하는 입력창과 전송 버튼이 있다. 전송 버튼을 누르면 사용자 메시지가 바로 목록에 나타나고 동시에 Claude에게 요청을 보낸다.

### 요구사항 원문에서
- `흐름 5: 완독 후 토론`: "2. 사용자가 텍스트로 답한다. 20턴 도달 시 AI가 마무리 멘트를 하고 입력이 닫힌다." — 입력창 활성화와 전송 로직
- `AI 기능 > 완독 후 토론`: "역할: '책 친구'. ... 한 번에 질문 1개, 답변은 3~4문장 이내" — 메시지 상세 표시 시 길이 고려(스크롤 최소화)

### 선행 작업이 남긴 것
- T-702: DiscussionRepository.startDiscussion()가 Discussion과 첫 AI 질문을 저장
- T-609: AiErrorCard 컴포넌트로 네트워크·키 오류와 재시도 버튼 공용. 여기서도 쓰임

### 주의할 점
- 메시지 로딩 중 전송 버튼 비활성화는 ViewModel의 isLoading 상태로 제어.
- 사용자 메시지는 전송 직후 목록에 추가하되, 데이터베이스 저장은 T-704에서.
- 스크롤: 새 메시지가 오면 자동 스크롤로 최신 메시지 보임.

### 완료 조건 체크 방법

- 전송 버튼: 로딩 중에는 비활성화되고, 로딩 끝나면 다시 활성화 확인

## 작업 메모

(2026-10-05)

- `ui/discussion/DiscussionScreen`(진입·골격·미리보기) + `DiscussionSections`(말풍선, 대기 표시, 입력 바, 첫 질문 바, 종료 바). 상단에 책 제목과 "남은 턴 n".
- 전송 시 사용자 메시지는 Repository가 즉시 저장하므로 DB flow를 통해 바로 목록에 뜬다(별도 낙관적 상태 없음). 대기 중에는 "답을 생각하고 있어요" 말풍선과 입력 비활성.
- 오류는 `AiErrorCard` 공용(T-609). 재시도는 실패 메시지가 있으면 재전송, 없으면 첫 질문 요청.
- 토론 입력창은 요구사항이 명시한 채팅이라 타이핑 원칙(세 곳)의 예외로 본다 — 사용자 확인 목록에 올림.
