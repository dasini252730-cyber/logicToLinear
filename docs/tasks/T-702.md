### 쉽게 말하면
사용자가 완독 후 "이야기해볼까요?" 버튼을 누르면, 앱이 새로운 토론 대화를 만들고, 사용자의 첫 발언을 기다리지 않고 Claude에게 첫 질문을 자동으로 요청한다. 예를 들어 별점이 높은데 글귀는 외로운 내용만 있으면 "별점과 글귀가 좀 다르네요. 왜 그렇게 느껴지셨나요?" 같은 질문을 던진다. 첫 질문은 데이터베이스에 저장되어 화면에 나타난다.

### 요구사항 원문에서
- `AI 기능 > 완독 후 토론`: "첫 메시지는 앱이 자동으로 요청한다(사용자 입력 없이). 예: 별점과 글귀 위치의 불일치, 한 줄 소감의 단어 하나를 짚는 질문." — 첫 질문 자동 요청 및 예시
- `흐름 5: 완독 후 토론`: "1. AI가 첫 질문을 던진다 (별점·한 줄·글귀를 근거로). / 2. 사용자가 텍스트로 답한다. ... / 3. 토론은 Discussion에 저장되고 책 상세에서 다시 볼 수 있다." — 토론 시작 및 저장 흐름
- `데이터 모델 > Discussion`: "messagesJson: [{role, content, at}] 배열, 최대 40개(20턴)" — 메시지 직렬화 형식
- `예외 처리`: "토론 중 네트워크 끊김 → 사용자 메시지는 로컬에 보관, 재전송 버튼" — 실패 처리는 다음 task지만, 여기서 Discussion 행은 생성됨

### 주의할 점
- Discussion 행은 성공했지만 첫 질문 요청이 실패하면, Discussion은 그대로 두고 사용자에게 "재시도" 버튼을 보여준다(T-706과 연결).
- 첫 질문은 DiscussionProposal 순수 함수로 생성하고(테스트 용이), DiscussionRepository에서 AiChat.complete() 호출. 예시: 별점·글귀·한 줄 소감을 입력으로 받아 "이 책에서 뭘 느꼈는지" 짚는 질문 생성.
- 메시지는 ChatMessage 직렬화 형식({role, content})으로 messagesJson에 저장. at 필드(타임스탬프)는 UI 표시용일 수도 있으므로 요구사항 재확인 시 필요.

### 완료 조건 체크 방법
- 토론 시작 후 Discussion.messagesJson을 파싱하면 [{role: "assistant", content: "..."}] 배열 1개 존재 확인
- 실패 시: 같은 bookId의 Discussion 행이 남아 있고, 다음 재시도에서 같은 행을 업데이트하는지 확인 (@Upsert의 동작 방식)

## 작업 메모

(2026-10-05)

- `DiscussionRepository.start(bookId)`가 행을 만들고(messagesJson "[]"), `requestFirstQuestion(id)`가 사용자 입력 없이 첫 질문을 요청한다. API는 user 메시지로 시작해야 하므로 `toChatMessages`가 숨은 시작 지시를 첫 user 메시지로 넣는다(저장·화면에는 없음). 이미 AI 메시지가 있으면 다시 묻지 않아 회전·재진입에 안전하다.
- 자동 요청은 `DiscussionRoute(fresh=true)`로 들어온 직후 한 번만(ViewModel init). 책 상세 목록에서 다시 열 때(fresh=false)는 자동 호출하지 않고, 첫 질문이 없으면 "첫 질문 받기" 버튼을 보인다(요구사항 "호출은 사용자 동작으로만").
- 실패하면 행은 남고 messagesJson은 비어 있다. 오류 카드(AiErrorCard)의 재시도가 `requestFirstQuestion`을 다시 부른다.
