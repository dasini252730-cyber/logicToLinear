### 쉽게 말하면

ML Kit의 한국어 텍스트 인식(OCR) 모델을 앱에 추가해서, T-202에서 받은 Bitmap을 넘기면 인식된 텍스트를 줄(Line) 단위로 받는다. TextBlock > Line 구조를 앱 내부 모델 OcrLine(text, boundingBox, 이미지 높이 대비 y 비율)으로 변환해서 다음 화면(문장 선택)에서 쓸 수 있도록 준비하고, 인식에 걸린 시간을 로그에 남긴다.

### 요구사항 원문에서

- `기술 스택 > OCR`: "Google ML Kit Text Recognition v2 (Korean) | 온디바이스, 무료, 오프라인 동작" — 선택된 OCR 도구와 제약 조건
- `글귀 OCR과 문장 선택`: "ML Kit `TextRecognition` Korean 옵션으로 `Text.TextBlock > Line` 구조를 받는다. 화면에는 Line 단위로 나열한다." — T-203의 정확한 API 구조
- `글귀 OCR과 문장 선택`: "선택 결과를 저장 전에 편집 가능한 텍스트 칸으로 보여준다. 오타 한두 글자는 여기서 고친다." — OCR 결과의 신뢰도를 사용자가 검수
- `페이지 번호 자동 인식`: "이미지 상단 15% 또는 하단 15% 영역에 있는 Line 중 숫자만으로 된 1~4자리 텍스트를 페이지 후보로 본다." — boundingBox의 y 비율이 필요한 이유

### 주의할 점

- **번들 vs 언번들**: T-004에서 이미 번들 방식(app 안에 포함)으로 결정했으므로, unbundled 모델(Google Play Services 다운로드)을 쓰면 안 된다. 의존성명 확인 필수: `com.google.mlkit:text-recognition-korean` (번들 O) vs `com.google.android.gms:play-services-mlkit-text-recognition-korean` (언번들 X).
- **OcrLine 모델**: boundingBox는 Rect로 절대 픽셀 좌표 (x, y, width, height). 페이지 번호 판정(상단·하단 15%)을 위해 y좌표를 이미지 높이로 나눈 0~1 범위의 비율도 함께 저장해야 한다. (T-207에서 사용)
- **인식 시간 로그**: `System.currentTimeMillis()` 또는 `System.nanoTime()`으로 시작 전후 시간을 잰다. 목표는 1초 내외이지만, 이 단계에서는 기록만 한다. 최적화는 후속 task.
- **라이프사이클**: `TextRecognition.getClient()` 하나를 싱글톤 또는 ViewModel에서 관리하고, 앱 종료 또는 화면 이탈 시 `recognizer.close()`를 반드시 호출한다. 메모리 누수·리소스 누적 방지.
- **오프라인 동작**: 번들 방식이므로 설치 직후 네트워크 없이도 OCR이 동작한다 (T-004 결과). 다만 앱을 처음 실행할 때 모델 초기화에 시간이 걸릴 수 있다 (1~2초).

### 완료 조건 체크 방법

- 한국어 책 페이지(예: 한글 문단 사진) 촬영 → 다음 화면(문장 선택)으로 이동 → 인식된 한글 텍스트가 줄 단위로 나열됨 확인
- 영문과 숫자가 섞인 페이지 촬영 → 영문도 인식되는지 확인 (한국어 모델이 라틴 문자도 함께 인식)
- Android Logcat에서 "OCR recognition took XXXms" 같은 로그 메시지 확인 (예: "OCR recognition took 850ms")
- `adb logcat | grep -i ocr` 또는 Android Studio Logcat 필터로 시간 로그 추적

## 작업 메모

(2026-10-05) T-201·T-202와 함께 구현.

- 의존성 `com.google.mlkit:text-recognition-korean:16.0.1`(번들, T-004 결정). 언번들 아티팩트는 쓰지 않는다.
- `ocr/OcrRecognizer`: `TextRecognition.getClient(KoreanTextRecognizerOptions)` 하나를 `AppContainer`가 lazy로 들고 있고 `HomeViewModel.onCleared`에서 `close()`. `recognize(bitmap, rotation)`은 `Task`를 `suspendCancellableCoroutine`으로 기다린다(`kotlinx-coroutines-play-services` 의존성 없이).
- `ocr/OcrLine`: text·left·top·right·bottom(세운 이미지 픽셀)·topRatio·bottomRatio(이미지 높이 대비 0~1). 변환은 ML Kit 타입에 의존하지 않는 순수 함수 `toOcrLines(raw, imageHeight)`로 빼서 테스트했다(정렬: 위→아래, 같은 높이면 왼쪽; 빈 줄 제거; 비율 0~1 클램프). rotation 90/270이면 세운 이미지의 폭·높이를 바꿔 기록한다.
- 인식 시간은 `Log.d("OcrRecognizer", "ocr: N lines in Xms (WxH)")`로 남긴다. 결과는 `OcrResult`로 `CaptureStore`에 넣어 문장 선택 화면(T-204)이 읽는다. 비트맵은 넣지 않는다.
- 빈 결과(`isEmpty`)는 `HomeViewModel`이 `ocrEmpty`로 바꿔 요구사항 문구 "글자를 찾지 못했어요. 더 밝은 곳에서 다시 찍어 주세요" + "다시 찍기" 다이얼로그를 띄운다(T-210 예외 처리 일부 선반영).
- 테스트 `OcrLineTest` 5개. 실제 인식 품질·시간은 ML Kit 네이티브가 JVM에서 돌지 않아 T-212 실기기에서 측정한다.
